# T1 · hub 协议适配层（帧解析 / 事件映射 / 命令编码 / 夹具） 方案

> 状态：草稿（待评审定稿）｜ 级别：中 ｜ 波次：1 ｜ 依赖：T0 ｜ 被依赖：T2（Framer）、T4/T6（InternalEvent 消费）、T8（回放夹具）
> 方案依据：方案第 3 章；hub `docs/design.md` 为协议唯一真相

## 契约

```typescript
// packages/adapter —— 全项目唯一允许出现 hub 协议字面量的实现包
decodeFrame(line: string): Frame | null
  // Frame = response | event{threadId, payload} | ui_request | heartbeat | hub_error | parseFailure(内部计数)
encodeCommand(cmd: PaiCommand): string     // thread/* | prompt(含 streamingBehavior) | steer | follow_up
                                           // | abort | compact | get_* | set_* | ui_response | auth/*
mapSessionEvent(threadId, ev, ctx): { ui: UiEvent | null; internal: InternalEvent | null }
attachFramer(stream, onFrame): { pause(); resume() }   // LF 唯一分隔；容忍 \r；U+2028/U+2029 不切；16MiB 整行旁路
```

- 纯函数、永不抛错：垃圾输入 → null/parseFailure 计数；未知帧类型 → 计数 + 采样日志（协议演进第一道防线）。
- 产物：`tests/fixtures/hub-frames/`（真 hub smoke 输出录制 + 手工构造的对话框/auth/错误帧）。
- 时序约定：event 帧顺序 = 事件顺序（hub 保证全局有序不交错），映射不重排。

## 问题域

- 处理：帧解码与分发；AgentSessionEvent → UiEvent/InternalEvent 双通道映射（message_update 按 assistantMessageEvent.type 三分流；toolCallId/toolName；message_end usage）；命令编码（prompt 在流式中必须带 streamingBehavior——由调用方语义决定，编码层只校验形状）；分帧与背压（高水位 1000 暂停/500 恢复）。
- 不处理：进程生命周期与心跳判死（T2）；InternalEvent 消费（T4/T6）；hub 侧语义（其仓库）；会话文件读取（T5）。

## 并发/一致性预算

- 单行 <0.1ms（纯函数）；Framer pending 高水位 1000；16MiB 行旁路不 parse；回调内禁 IO。

## 拆分

```
packages/adapter/{frame-decoder.ts, session-event-mapper.ts, command-encoder.ts, framer.ts, __test__/}
tests/fixtures/hub-frames/{smoke,dialogs,auth,errors}/
```

依赖：contracts（含 hub 镜像类型）；不依赖其他任务实现。

## 实施顺序（每步独立测试 + 四门全绿后提交）

| # | 内容 | 单测 | 验收 |
| --- | --- | --- | --- |

## 裁决

- 镜像类型抄录自 hub（T0 裁决引用）；夹具「真录制优先、手工构造补场景」：**默认裁决**，否决窗口至定稿。

## 测试口径

- 契约断言：五类帧判别联合穷举；命令全集 == contracts PaiCommand 词表；映射表逐条锁定。
- 边界：空串/null/数字/截断 JSON/超长行/字段缺失；晚到 ui_response（透传不解析）。
- 表驱动：帧表、事件映射表、命令表、夹具矩阵。
- 分层：单元 + 夹具回归（每 PR）；真 hub 集成归 T9 装置。
