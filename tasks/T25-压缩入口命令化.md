# 压缩入口命令化（按钮下线，`/compact` 斜杠命令）方案

> 状态：已核销（2026-09-10）。后继：用户裁决推翻裁决①（渲染层拦截），/compact 收敛为 hub 侧机制（T26：get_commands builtin 第四源 + prompt 通路拦截）；本任务的渲染层注册表桥（builtin-commands）与 session/compact 直调链已由 T26 B2 整体下线，命令入口（斜杠补全/高亮/暂存排除词法）与 customInstructions 语义（后随文字为压缩附加指示）经 hub 延续生效。
> 级别：中（跨 contracts / main 路由 / live 控制层 / composer 拦截与目录合成 / strings；契约参数扩展但无协议变更；无并发新语义）
> 用户裁决（AskUserQuestion 未获答复，按推荐项默认推进，否决窗口随实现同批交付）：
> ① 执行通路 = 渲染层拦截（不动 hub 仓库）；② `/compact` 后随文字作为压缩附加指示（customInstructions）透传；③ T24 在途变更先行收口提交后再动工。

## 背景（现状事实）

- 压缩入口：输入框底行按钮（`ComposerActionsRow`）→ `WorkspaceActions.compact()` → `LiveController.compact(threadId)` → `session/compact` → hub `{type:'compact'}`。
- hub 侧 `get_commands` 命令目录三源（extension/prompt/skill）**没有** compact 条目；hub prompt 通路**不拦截** `/compact` 文本——当前手输 `/compact` 发送会原样作为用户消息发给模型（误发风险，本方案顺带根治：把它变成有效命令）。
- hub `CompactCmd` 已有 `customInstructions?` 字段（透传 `AgentSession.compact`，pi TUI 的 `/compact 保留重点` 同源）；Pai 契约 `session/compact` 目前只收 `threadId`。
- 渲染层高亮/补全/原子删除只认「命令目录里存在该 name」——本地合成条目入目录后三者自动生效（`command-highlight.ts` 注释既有预告）。

## 契约

### 外部契约（contracts）

- `session/compact` params：`threadOnly` → `{ threadId: z.string().min(1), customInstructions: z.string().min(1).optional() }.strict()`（可选参数有缺省；空串无意义由 min(1) 拒绝，渲染层 trim 后空串不传）。result 不变（`z.null()`）。
- `CommandViewSchema` **不动**（hub 三源是目录真相；内置命令不过 IPC、不镜像 hub）。
- hub 协议零变更（不动 pi/app 仓库）。

### 渲染层内部面

- 新 `composer/builtin-commands.ts`（内置命令注册表，单一真相）：
  - `BuiltinCommand = { name: string; description: string | null; source: 'builtin' }`；
  - `ComposerCommand = CommandView | BuiltinCommand`（目录消费面的统一类型，只住渲染层）；
  - 清单当前一条：`{ name: 'compact', description: <strings 本地化>, source: 'builtin' }`；
  - `mergeCommands(hubCommands)`：合成 `[...builtin 让位去重, ...hub]`——hub 目录出现同名命令时本地条目让位（hub 是命令目录真相）。
- `WorkspaceActions.compact`：`() => void` → `(customInstructions?: string) => Promise<boolean>`（true = 已受理；失败/拒绝的 pushNotice 留在实现内部，与现状一致）。
- `LiveController.compact`：`(threadId: string)` → `(threadId: string, customInstructions?: string)`。
- 目录消费面类型放宽 `readonly CommandView[]` → `readonly ComposerCommand[]`：`use-live-workspace`（commands state + view 出口）、`workspace-main` 装配、`Composer`、`PromptInputArea`、`command-groups`（`'builtin'` 分箱归「命令」组）、`command-highlight`（`HighlightRange.source` 放宽）。
- `SessionControls` 删 `compacting` / `compactLabel` / `onCompact` 三字段；`ComposerActionsRow` 删压缩 IconButton；`Composer` 删 `onCompact` / `compacting` / `compactLabel` props；`workspace-main` 删对应装配。
- strings：删 `composer.compact`；增 `composer.builtinCompactDescription`（菜单描述）、`flow.compactBusy`（压缩中重复触发提示）、`flow.compactNoImages`（命令携图拒绝）。
- 事件时序：无新事件；`compaction_start/end` → 横幅「正在压缩上下文…」面不变（`workspace.compacting` view 字段保留，ThreadBanner 照旧）。

## 问题域

### 处理

- 提交拦截（`screens/submit-draft.ts`，与 `! ` bash 同层同型）：trim 后首 token 精确为 `/compact`（后随空白或结尾，`/compactfoo` 不劫持）→ 调 `actions.compact(customInstructions)`，成功清草稿；后随文字 trim 为 customInstructions（空串 → undefined）。
- 携图拒绝：命令带附件 → `flow.compactNoImages` 提示，不提交（对齐 bash 分支）。
- 压缩中防重复：`actions.compact` 实现内读 store 活线程 `compacting` 态拒绝（`flow.compactBusy`；原按钮 disabled 防线的等价迁移）；hub 错误（如 stream_busy）仍经 `flow.compactFailed(reason)` 兜底。
- 生成中（streaming）不进暂存：`/compact` 是即时操作（同 `! ` 直执行语义）；hub 在流式中拒绝 → compactFailed 提示闭环。
- 内置命令进补全菜单：`/` 弹层可见、Enter/Tab 采纳、首 token 高亮、原子删除——目录合成后自动生效，无需新交互代码。
- 删压缩按钮与全部 prop 链。

### 不处理（归属）

- hub 仓库改动（`get_commands` 加 compact 条目、prompt 通路拦截）——外部仓库流程；渲染层 `mergeCommands` 的同名让位已为将来收敛留好接口。
- compacting 横幅 / 自动压缩（threshold/overflow）/ queued drafts 机制——现状不动。
- 新任务页（无会话 commands 为空）：`/` 触发不启用、`/compact` 不可用——无会话无上下文可压缩，合理不摆假能力。
- 其他内置命令（子代理等）入驻注册表——机制就位，本批只进 compact 一条。
- `/compact` 之外的未知斜杠词——维持现状：原样作为消息发送（hub 解释）。

## 并发/一致性预算

- 无新定时器、无新 IO；拦截与解析均为纯函数；目录合成只发生在 `setCommands` 单点（切会话先清空既有行为不变；`command/list` 拉取失败仍落内置条目——本地 builtin 不依赖 hub 数据）。
- 压缩中重复触发 = 本地 store 态一读一判（compacting 态由折叠层事件维护，`compaction_end` 就地终态）。
- 已知受理窗口竞态（对抗审查 P2-3，如实记录）：`session/compact` invoke 在途 → `compaction_start` 事件经 50ms 批推到达前的窗口内，二次提交可直达 hub；结局由 hub 错误（拒绝重复压缩）兜底为 `compactFailed` 提示，不双压缩、不崩溃。本地预置 compacting 需与折叠层事件幂等合并，留待后续批次。

## 裁决

- 默认裁决 A：hub 同名命令让位（`mergeCommands` 去重以 hub 为先）——目录真相在 hub，本地条目只是「hub 尚未提供」的桥。**让位只覆盖目录展示面**：提交拦截仍由本地注册表判定（当前同名即压缩、语义等价）；hub 目录真出现 `compact` 条目之日需重新裁决拦截面是否同步让位（对抗审查 P2-2 落档）。否决窗口：随实现同批交付。
- 默认裁决 B：`/compact` 不进生成中暂存（即时操作，直执行语义；判定词法 = `isImmediateSubmit`，bash 容忍前导空白、命令严格行首——与命令高亮及 pi 的 startsWith("/") 解释一致）。同上。
- 默认裁决 C：无会话面不注册内置命令（commands 数组为空时 `/` 触发本来就不启用，不特判）。同上。
- 默认裁决 D（对抗审查 P1-2 落档）：内置命令分派是 exhaustive switch + never 编译锁 + default 显式拒绝（`commandUnhandled` 提示）——注册表将来新增命令而分派漏接时，编译期先红、运行期绝不静默把命令文本发给模型。
- 审查处置驳回附理由（P1-1 之 busy 用例）：workspace-actions 是 workspace-runtime 单例装配面（store/controller/bridgeClient 不可注入），全文件既有零测试；`threads[tid]?.compacting` 的语义已由折叠层测试（fold-events `case 'compacting'`）锁定，拦截层「actions 拒绝 → 草稿保留」由 submit-draft 症状回归用例锁定。单例注入重构超出本批，挂账后续。

## 测试口径

- 契约级：`session/compact` params——缺省/合法/空串/未知键矩阵（contracts schema 样本）+ controller 透传表驱动（不传 → params 仅 threadId；传值 → 透传）。
- 拦截表驱动（submit-draft）：裸 `/compact` 触发且清草稿；`/compact 保留 X` → customInstructions='保留 X'；`/compactfoo` / `/compact-x` / 文中段 / 前导空白不拦截走普通提交；首 token 后空白首尾收敛、内部原样；携图拒绝；actions 返回 false 不清草稿；`! ` 优先级。
- 即时判定表驱动（isImmediateSubmit）：bash（含前导空白）/ 命令（严格行首）两族词法、普通消息、空文本。
- 注册表：mergeCommands 合成顺序与 hub 同名让位、拉取空目录内置仍在；清单 name 无前导斜杠；词法大小写敏感、换行分隔命中。
- 分箱/高亮：builtin 条目进「命令」组；`/compact` 首 token 高亮命中；`/compact 附加文字` 高亮仅首 token。
- 按钮：`ComposerActionsRow` 不再渲染压缩键（类型面 SessionControls 字段删除即防线）；无会话面 session=null 行为不变。
- 回归：压缩中重复触发由 actions 层拒绝（submit-draft 层「拒绝→草稿保留」症状用例锁链路；busy 判定本体挂账见裁决节）；生成中 `/compact` 不入 queuedDrafts（isImmediateSubmit 词法锁定）。
