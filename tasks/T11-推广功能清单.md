## A. 会话与对话

**A1. 会话重命名** · P0

依据：〔协议〕set_session_name；〔本地〕registry。

**A2. 会话内搜索（Ctrl+F）** · P1
当前对话流内的全文搜索（已水化条目），命中滚动定位+高亮；跨会话搜索进 N2。
依据：〔本地〕。

**A3. 侧栏会话过滤（搜索框生效）** · P0
侧栏顶部搜索框目前是空操作：按标题/项目名/消息内容前缀过滤会话列表。
依据：〔本地〕。

**A4. 项目分组与项目记忆** · P1
侧栏按 cwd 项目真实分组（当前只有扁平列表+项目行）；记忆最近使用的 cwd 与每项目默认模型/思考档，新建会话时预填。
依据：〔本地〕registry/settings。

**A5. 分叉与重试（fork/clone）** · P1
消息菜单「从这里重试 / 编辑重发（真分叉）」：`fork(position:"before")` + 重新提交；「克隆当前状态继续」：`clone`。响应换新 threadId 自动重路由窗口（api.md checklist 遗留项）。
依据：〔协议〕fork/clone/get_fork_messages。

**A6. 会话树导航** · P2
`get_tree` 渲染分支树侧板，点击 leaf `navigate_tree` 跳转（不换文件不换 id）；配合 A5 使用。
依据：〔协议〕get_tree/navigate_tree。

**A7. 排队消息管理** · P1
排队徽标展开：逐条显示 steering/followUp 待发消息，支持单条点击改投递方式（协议无单条删除，仅「清空全部」= clear_queue）；发送时生成中的轮次提供「插入当前轮(steer)/轮后发送(followUp)」显式选择。
依据：〔协议〕queue_update/steer/follow_up/clear_queue（单条增删为 hub 缺口，见 P2 节）。

## N. 依赖 hub/外部决策的缺口（当前协议不支持，需先推动 pai-cli）

**N1. MCP 服务器管理（CRUD）** —— pi/pai-cli 当前**无 MCP 支撑面**（coding-agent 全源码无 mcp 实现），无法在客户端单侧实现。可选路径：①推动 hub 增加 MCP 客户端与配置命令；②以 pi 扩展形式做 MCP 桥（扩展文件管理见 E4/F2 同机制）；③接入外部 MCP 聚合进程作为「自定义 provider+工具」形态。需要你裁决方向。
**N2. 排队消息单条删除/编辑** —— 协议仅 clear_queue 全清；需 hub 增加单条操作。
**N3. 会话文件删除** —— 协议无删除命令；需 hub 增加（Pai 直接删 agentDir 文件可行但绕过 hub 会话表一致性，不建议单侧做）。
**N4. 会话导出（HTML）** —— pi SDK 能力未上协议；需 hub 增加 export 命令。
**N5. 指定 agent 开轮** —— prompt 无 agent 参数；需 hub 扩展（对应 F3）。
**N6. 技能单粒度启停** —— 取决于 pi 资源系统 enabled 位语义；实现前与 hub 对齐（对应 E2）。
