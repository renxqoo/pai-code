## 0. 现状诊断（实测，可复现；撰写于 2026-09-23，hub 缺口一节已随 H 路线落地失效，保留作根因记录）

**界面**：技能分区只有「搜索框 + 刷新按钮 + 每行启停开关」，**没有任何导入入口**
（`apps/electron/src/renderer/src/settings/skills-section.tsx` 全文 87 行，卡片体在 :54-79）。
空态文案「未安装用户级技能。」（`strings/zh-settings.ts:142`）没有任何出路。

**数据链**：清单唯一来源 = hub `skills/list`，hub 侧只扫
`~/.x-harness/skills`（user）与 `<cwd>/.x-harness/skills`（project，须受信）
（`x-harness/apps/host-hub/src/host/skills-admin.ts:20-24`、`worker/assembly.ts:111-121`）。
主进程收窄器丢弃 `path`/`description`，只留 `{name, enabled, source}`（`packages/api/src/verbs/settings.ts:74-90`）。
app 侧旧的本地技能扫描器（T13 的 `skills-inventory.ts`）已在 T38/T39 删除，**app 现在没有任何
本地技能面**（`ls apps/electron/src/main` 无该文件）。

**hub 命令面缺口**（已随 H 路线补齐）：撰写时 `COMMAND_NAMES` 共 58 项（app 镜像 58=58），技能域只有
`skills/list|set_enabled|remove`（`x-harness/apps/host-hub/src/protocol/commands.ts:98-100`）——没有创建/安装/导入面。
**现况**：hub 已扩至 **60** 命令（`skills/inspect` + `skills/install`，`COMMAND_NAMES` 58→60），
形态判定/名围栏/原子落盘/预算/回滚全在 hub 侧，详见 `x-harness/docs/SKILL-INSTALL.md`（定稿 2026-09-23）。

**本机四根实测**（以 x-harness 装载器规则逐条判定；明细见 §9）：

| 源根 | 子目录数 | 可直接导入 | 拒（原因分类） |
| --- | --- | --- | --- |
| `~/.x-harness/skills`（现役目标根） | — | — | **目录不存在**（首次导入需创建） |
| `~/.agents/skills`（pi/agents 形态） | 15 | **12** | name≠目录名 1（`tavily` → `name: tavily-cli`）、无 SKILL.md 2、嵌套 1（`@user_4998424d/rxopen-hot`） |
| `~/.pi/agent/skills` | 17 | **11** | 非扁平 frontmatter 5（`metadata.requires.bins` 用块列表 `- x`，扁平解析整档拒）、name≠目录名 1、无 SKILL.md 1 |
| `~/.claude/skills` | 5 | **2** | 无 SKILL.md 2、name≠目录名 1、嵌套 1（`@user_4998424d/tavily-cli`） |

**这就是「无法导入」的全部根因**：没有入口 × 目标根不存在 × 既有技能形态（嵌套、name 不匹配、
块列表 frontmatter）三处与 x-harness 装载器规则不兼容，而界面既不提示也不诊断。

**伴生缺陷（D-1，已在 H 路线同轮修复）**：`removeSkill` 删的是 `skill.path`，而 `SkillMeta.path` =
**`SKILL.md` 文件路径**（`packages/skill/src/loader.ts:80`），故「删除技能」只删掉 SKILL.md，
**技能目录与其捆绑文件（references/scripts）全部残留**；残留目录此后每次装载都产生一条
`unreadable ... SKILL.md` 告警（`loader.ts:61`）。已修：user 级移除 = 删整目录（回归用例
`x-harness/apps/host-hub/src/__test__/coverage-final.test.ts`，症状命名）。

**伴生缺陷（D-2，已同轮修复）**：`skills/set_enabled` 带 `cwd` 在全新项目（无 `.x-harness` 目录）ENOENT。

## 1. 契约（外部，app 侧新增两条；落盘与形态判定经 hub）

H 路线下 app 契约保持面向渲染层的两条不动，但**实现不再镜像任何 x-harness 规则**：
形态判定逐候选调 hub `skills/inspect`，落盘调 hub `skills/install`（单一判定源，漂移面归零）。

```ts
// packages/contracts/src/api.ts
/** 技能候选扫描：无 sourcePath = 扫固定源根；有 = 扫该目录（须为对话框已批准路径）。 */
'skills/candidates': {
  params: z.object({ sourcePath: z.string().min(1).optional() }).strict(),
  result: z.object({ candidates: z.array(SkillCandidateViewSchema) }).strict(),
},
/** 导入单个技能：经 hub `skills/install` 复制源目录到 user 级技能根（~/.x-harness/skills/<name>/）。 */
'skills/import': {
  params: z.object({
    sourcePath: z.string().min(1),
    /** 目标目录名；缺省 = 源 SKILL.md 的 frontmatter name（装载器要求二者一致）。 */
    name: z.string().min(1).optional(),
    /** 同名已存在时是否覆盖（缺省 false = 拒）。 */
    overwrite: z.boolean().default(false),
  }).strict(),
  result: z.object({
    skills: z.array(SkillViewSchema),          // 写后完整清单（同 setEnabled 范式）
    imported: z.object({ name: z.string(), path: z.string() }).strict(),
  }).strict(),
},
```

```ts
/** 候选视图（state = 三态判别，problem = 中性英文诊断，文案在 strings）。 */
type SkillCandidateView = {
  /** 建议目标名 = frontmatter name（缺省）/ 源目录名（无法读 frontmatter 时） */
  name: string
  description: string
  /** 源技能目录绝对路径（SKILL.md 的父目录） */
  sourcePath: string
  /** 来源根标签：agents | pi | claude | picked（手动选择目录） */
  origin: 'agents' | 'pi' | 'claude' | 'picked'
  /** ready = 可直接导入；rename = name≠源目录名（导入时自动校正）；blocked = 装载器必拒 */
  state: 'ready' | 'rename' | 'blocked'
  /** blocked/rename 的中性英文原因（例：`frontmatter line 6 has no colon`） */
  problem: string | null
}
```

**错误形态**（API 级 `ApiError.kind`，由 hub 错误码 + `SkillProblem` 七码映射，不新增判定逻辑）：
`skill_source_invalid`（源不在批准根之下 / 无 SKILL.md / 越界）、`skill_invalid`（hub
`invalid_input` + 非 `name_invalid` 的 SkillProblem：non_flat_frontmatter / oversized / missing_*）、
`skill_name_invalid`（hub `name_invalid`）、`skill_exists`（hub `name_conflict`）、
`skill_write_failed`（hub `io_failed` / `internal` 或回滚失败）、
`skill_not_registered`（落盘成功但回读清单不含该名 —— **镜像漂移的显式出口**）。

**不变的既有行为**：`skills/list`、`skills/setEnabled`、`hub skills/set_enabled` 全不动；
`SkillView` 本轮不加字段（P1 可选加 `description`，hub 响应里已有）。

## 2. 问题域

**处理**
1. 候选发现（app 侧）：扫 3 个固定源根（`~/.agents/skills`、`~/.pi/agent/skills`、`~/.claude/skills`）
   或用户经对话框选择的任一目录；深度 1 与深度 2（嵌套形态拍平）两级；
2. 逐候选校验（**hub `skills/inspect`**，单一判定源），三态分级 + 可行动诊断；
3. 落盘（**hub `skills/install`**）：目标名校正（`name` 覆盖由 hub 改写副本 frontmatter）、冲突处置
   （默认拒 / 覆盖带备份回滚）、目录树预算把关 —— 全部 hub 侧，app 不落盘；
4. 批量导入（多选 → 逐条落盘 → 汇总 → **单次**重开活跃会话）；
5. 生效闭环：落盘 → 若该名在 `skills.disabled` 名单则移除 → 回读清单断言在场 → 重开 live 会话；
6. UI：技能分区「导入技能」入口 + 导入对话框（候选列表 / 选择文件夹 / 预览 / 命名 / 冲突 / 进度 / 汇总）。

**不处理（归属显式）**

| 不处理 | 归属 / 理由 |
| --- | --- |
| .zip / .tar.gz 打包导入 | 无现成解压依赖（lockfile 里的 `unzipper` 是 electron-builder 的传递 dev 依赖，不得进产品码）+ 解压需 zip-slip/大小炸弹防护；用户可自行解压后选文件夹。挂账 |
| git / npm / URL 安装、技能市场 | T11 E4（P2）；引入网络拉取 + 代码执行面，本轮零涉及 |
| 项目级技能导入（写入 `<cwd>/.x-harness/skills`） | T11 E3 裁决「项目级随仓库走，只读展示」；改用户仓库文件不在本轮 |
| 技能内容编辑 / 新建 SKILL.md 模板 | T11 E3，独立任务 |
| 项目级技能在清单里展示 | 现契约 `skills/list` 不带 cwd 只返 user 级，文案却提「项目级只在受信会话出现」（`zh-settings.ts:143`）—— 事实展示缺口，另立任务，本轮不动（属 scope creep） |
| worker 侧技能热重载 | x-harness 装载是装配期一次性快照（`packages/skill/src/plugin.ts:19-24`、`docs/SKILL.md §1.3`）；生效靠重开会话，与既有启停编排同路径 |
| 放宽装载器对块列表 frontmatter 的拒收 | x-harness 侧设计裁决（`md-frontmatter/parse.ts` 扁平语义）；本方案只做可行动诊断，不替上游改语义 |

## 3. 方向性裁决（用户裁决已落，2026-09-23）

- **【D1=H，用户裁决 2026-09-23】落盘写者 = x-harness hub**：新增 `skills/inspect`（入参
  `dirs[]`，批量三态 + 问题码）与 `skills/install`（`{sourcePath, name?, overwrite?}`），
  hub 侧复用装载器校验与拷贝。app 侧**不实现任何校验规则**，`SkillInstallPort` 转正为 hub
  命令适配（`skills/install` + `skills/inspect` typed 调用）。
  - **改判理由**（推翻原默认 A 的论证）：预览与落盘的判定必须是**同一份**规则；A 路线要求 app
    镜像 x-harness 装载器语义（`md-frontmatter` 扁平解析、1 MiB 硬门、name 围栏），两仓双实现
    的漂移面长期不可控（§7 的规则表镜像测试只是漂移的探测器，不是消除器）。H 路线把判定收敛到
    hub 单点，app 只做候选发现/预览编排/文案本地化 —— 恰是 `docs/SKILL-INSTALL.md §0`
    「**安装是 hub 的职责**，渠道是 host 的事」的既有边界。
  - **代价如实**：跨仓成本（x-harness 命令面 + 词表 + 其规约四门）已支付（hub 侧本轮落地）；
    app 对 hub 有版本依赖（需 hub ≥ 60 命令面；hub 缺 `skills/install` 时 `skill_not_supported`
    降级，见 §6）。
- **【D2】源根清单固定三条 + 手动选择**：`~/.agents/skills`、`~/.pi/agent/skills`、`~/.claude/skills`
  写死为主进程常量（渲染层不得传任意根；`sourcePath` 只作「在批准根之下」的收窄参数）。
  不扫 `~/.x-harness/skills`（它就是目标根，扫它只会得到「已安装」）。
- **【D3】命名**：目标目录名缺省 = frontmatter `name`（装载器硬性要求 name == 目录名，
  `loader.ts:79`）。用户改名时传 `name` 给 hub `skills/install`，**由 hub 同步改写副本 SKILL.md
  的首个 `name:` 行**（源文件不动）——不这么做就必然「导入成功但技能不注册」，是最容易踩的静默失败。
- **【D4】冲突**：同名目标存在 → 缺省拒（`skill_exists`），UI 给「覆盖」显式二次确认；
  覆盖走 hub 的备份 + 回滚（`SKILL-INSTALL.md §2`），绝不「先删后拷」。
- **【D5】批量**：勾选多个候选 → 渲染层**串行**逐条调 `skills/import`（失败逐条隔离、进度可见），
  全部结束后统一刷新清单 + **单次**重开（不是每个技能重开一次）。
- **【D6】生效闭环**：落盘 → 名在 `skills.disabled`（`~/.pai/agent/hub-settings.json`）则调
  `skills/setEnabled(name, true)` 清名单（否则导入即显示「已关闭」）→ 回读 `skills/list` 断言在场
  （不在 → `skill_not_registered`）→ 走既有 `applySkillToggle` 的串行重开链重开 live 会话。
- **【D7】不做 zip/git/npm/市场/项目级/编辑器**（见 §2 表）。
- **【D8】伴生**：技能卡加「删除」入口（`skills/remove` 已有命令但 app 无入口）**同轮做**：
  与导入是同一张卡的一对动作；目录残留缺陷（D-1）hub 侧已修。

## 6. 并发 / 一致性 / 安全预算

- **串行链**：导入与启停共用一个串行链（`skillToggleChain` 同型），任一次技能变更在途时后续追加队尾；
  重开次数：批量 N 条 = **1 次**重开。
- **原子性（hub 侧，`SKILL-INSTALL.md §2`）**：暂存目录 = **技能根的子目录** `.skill-install-<rand>` →
  校验副本 → 覆盖时旧目录 rename 进暂存 `.skill-install-bak-<rand>` → rename 新目录就位 → 删备份。
  任一步失败：清理 + 回滚备份 + `io_failed`。**半成品永不暴露**（装载器只扫技能根直接子目录；
  暂存根被 symlink 占位 → 拒不写入）。app 侧无需再做落盘原子性。
- **预算**：单技能目录树 ≤ 2000 文件 / ≤ 100 MiB；SKILL.md ≤ 1 MiB —— 全在 hub 侧把关。
- **白名单与围栏**（app 侧安全，必测）：
  1. `sourcePath` 经 **realpath 归一后**必须位于「批准根」（三个内置根 ∪ `pickedDirectories`）之下
     ——否则被攻陷的渲染层可把 `~/.ssh` 之类目录拷进技能根，再借模型 read/bash 工具读走；
  2. 目标名围栏 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` 且非 `.`/`..`（app 提交前预检 + hub
     `assertInstall` 硬门双侧；防 `name: ../../..` 越界写盘）；
  3. 源技能目录若为符号链接：取 realpath 作源（装载器跟随 symlink 目录语义一致），
     **嵌套 symlink 不 dereference**（hub 拷贝规则），避免把技能树外的内容整棵拷进来；
  4. 覆盖必须显式（默认拒）；对话框与落盘各自单飞，防并发叠弹/叠写。
- **降级**：hub 无 `skills/install`（旧 hub，58 命令面）→ `skill_not_supported`，
  UI 提示升级 x-harness；hub 未就绪 → 沿用既有 host 未就绪降级文案。
- **风险告知**（UI）：技能可捆绑脚本，模型经 bash 工具执行时受权限门约束（不是本功能引入的新面，
  但导入是唯一的「把外部内容放进信任目录」的动作，需一次性提示）。
