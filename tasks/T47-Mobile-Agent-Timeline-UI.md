# 移动端 Agent 任务时间线 UI/UX 重构

> 状态：已核销
> 级别：中
> 范围：`apps/mobile`

## 1. 目标

将移动端对话从逐条日志式消息流重构为适合手机阅读的 Agent 任务时间线。界面借鉴 Codex 与 Claude Code 的共同信息架构：用户意图和 Agent 结论始终优先；思考、读取、搜索、命令与编辑等过程信息收敛为可展开的活动摘要；运行状态持续可见但不占据正文空间。

只借鉴信息层级和交互原则，不复制品牌资产、图标、配色或具体布局。

## 2. 契约

### 2.1 时间线分组

- `user`、`assistant`、`system`、`code` 保持独立消息边界和原始顺序。
- 连续的 `thinking`、`tool`、`status` 合并为一个 `activity` 块；任一正文或代码消息都会结束当前活动块。
- 空数组返回空时间线；未知或缺少可选元数据的消息使用安全缺省，不抛异常。
- 分组只改变展示结构，不修改 `ChatMessage` 公共契约、原消息顺序或会话数据。

### 2.2 活动摘要

- 成功活动默认折叠，摘要显示完成状态、活动数量、总耗时和最后一个有效结果摘要。
- 失败活动默认展开，摘要和失败步骤使用警示色；成功步骤保持低对比度。
- 运行活动默认折叠，只显示当前动作、已完成数和总数；用户可主动展开完整步骤。
- 展开后按原始顺序展示过程摘要与工具步骤。成功步骤只展示标题和结果摘要；失败或运行步骤额外展示详情。
- 活动块具备 button role、expanded state 和明确的无障碍标签。

### 2.3 正文与运行态

- 用户请求使用低对比度任务卡，不使用高饱和聊天气泡。
- Agent 正文使用开放排版，不套卡片；正文与活动摘要通过留白建立层级。
- 活跃执行清单初始为收起态；收起态只显示当前动作和整体进度，展开后才显示步骤列表。
- 代码结果保持独立工件卡，并继续支持长内容折叠。
- 权限请求继续独立展示，不并入活动摘要，避免隐藏需要用户决策的操作。

### 2.4 对话列表

- 每行按“状态与标题 → 最近结果 → 项目和时间”三层展示。
- 当前会话使用轻背景标识，不增加装饰性边框。
- 工作中、暂停、未读状态使用文字或单一状态点表达，不重复叠加多个提示。
- 更多操作维持 44pt 触控目标；列表密度紧凑但不牺牲可读性。

## 3. 问题域

### 处理

- 时间线分组算法和活动摘要组件。
- 用户消息、Agent 正文、运行中执行清单的视觉层级。
- 历史抽屉与对话列表行的信息密度、当前态和运行态。
- 相关中文文案集中管理。
- 单元、组件、移动视口交互和视觉走查。

### 不处理

- host-hub、真实流式事件和消息持久化由移动端应用服务接入任务负责。
- Markdown 解析、完整 diff、终端 transcript 和日志搜索由后续内容渲染能力负责。
- 设置持久化、账号系统和发布配置不属于本次任务。
- 不修改 Electron UI、共享协议或主进程行为。

## 4. 并发与性能预算

- 分组算法单次线性遍历，时间复杂度 `O(n)`，不创建定时器或订阅。
- 折叠态不挂载步骤详情；只有用户展开的活动块渲染内部列表。
- 当前夹具规模下 390×844 首屏无横向溢出；长文本必须截断或自然换行。
- 本次保持现有滚动容器，不把列表虚拟化与视觉重构混在同一批次；长会话虚拟化归属真实数据接入时的数据量级设计。

## 5. 拆分

- `timeline-blocks.ts`：唯一时间线展示分组规则。
- `activity-block.tsx`：统一承载 thinking/tool/status 摘要与展开详情。
- `timeline-list.tsx`、`message-item.tsx`：只负责块级分发。
- 用户、助手、代码、权限组件：保持各自单一职责。
- `active-execution.ts`、`execution-todo-dock.tsx`：运行态筛选和收起式进度展示。
- `session-row.tsx`、`history-drawer.tsx`：对话列表层级和当前态。
- `strings/zh.ts`：新增时间线和对话列表文案。

被统一活动块替代的 thinking、tool、status 独立展示组件直接删除，不保留双轨路径。

## 6. 实施顺序

1. 更新分组测试，建立 mixed activity、正文边界、失败与垃圾元数据口径。
2. 实现统一 `activity` 块并删除旧过程组件。
3. 收敛用户消息、Agent 正文和运行中执行清单。
4. 重构历史抽屉与会话行，补当前态和状态语义。
5. 更新演示夹具与组件测试，执行移动端定向测试。
6. 执行 lint、typecheck、build、test、覆盖率与双平台 bundle。
7. 独立对抗审查后，使用 bw 在 390×844 视口验证折叠、失败展开、运行态、长对话、抽屉、深色模式和无障碍状态。

每一步保持单轨实现；旧组件一旦替换即删除。

## 7. 裁决

- 用户裁决：整体风格参考 Codex 与 Claude Code，重点优化对话列表、消息展示和大量工具调用的合理折叠。
- 默认裁决：采用任务时间线而非传统左右聊天气泡；过程信息按连续活动聚合，成功折叠、失败展开、运行中单行摘要。
- 默认裁决：保留过程的可审计入口，不默认展示完整日志，也不永久隐藏失败原因。
- 默认裁决：本次不扩张到真实 Agent 接入，确保 UI 重构可以独立验证和回滚。

## 8. 测试口径

### 分组单元测试

- thinking/tool/status 混合连续输入合并为一个 activity。
- user/assistant/system/code 分别切断 activity，正文顺序不变。
- 空输入、单条过程消息、缺少 status/title/summary/duration 的消息安全降级。
- 多轮用户请求不会跨轮合并活动。

### 组件测试

- 成功 activity 默认折叠，点击后按原顺序显示详情。
- 任一失败步骤使 activity 默认展开并显示失败信息。
- 运行 activity 摘要显示当前动作和进度。
- 折叠和展开均暴露正确 accessibility state。
- 用户消息、Agent 正文、代码、权限请求仍可达且不被错误合并。
- 执行清单默认收起，展开后显示全部步骤。
- 会话行显示当前、工作中、暂停、未读的封闭状态组合，更多操作仍可点击。

### 回归与真机走查

- 原有时间线折叠、代码截断、滚动不抢占、权限确认和 Composer 测试继续通过。
- bw 390×844 检查：首页进入示例会话、成功活动展开/收起、失败主动暴露、运行态收起/展开、抽屉当前会话、设置返回。
- 浅色和深色均无横向溢出；console/errors 为空。
