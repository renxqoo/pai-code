# T5 · 视图持久化（node:sqlite 视图账本 / 恢复快照 / SessionReader 兜底） 方案

> 状态：草稿（待评审定稿）｜ 级别：中 ｜ 波次：1 ｜ 依赖：T0 ｜ 被依赖：T4（快照/落库）、T7（handlers/设置）
> 方案依据：方案第 5 章
> 职责边界：hub 管会话真相源与全部 agent 状态；本任务只存「展示层事实」——对话分组、thread 映射与恢复快照、用户偏好、用量聚合。调试事件缓冲为进程内环形，不落库。

## 契约

```typescript
// packages/infra/store —— 实现 core 的 StorePort（node:sqlite DatabaseSync）
threads:       upsertThread(t) / getThread(id) / listActive() / markStatus(id, status)
               // thread_id PK、session_path UNIQUE、conv_id、cwd、model、trusted、status、时间戳
conversations: list/create/archive/pin
usage:         addUsage(convId, tokens) / todayUsage()        // usage_daily，本地时区日界
settingsKv:    get/set（zod 校验）
debugRing:     进程内环形缓冲（上限 4MB 自动丢弃），仅排障导出，不落库
// SessionReader（worker，兜底）：readTail(sessionPath, n) / getToolResult(sessionPath, toolCallId)
```

- 错误形态：库损坏 → `{ok:false, reason:'corrupt'}` 备份重建（只损失排序/分组，会话零损失）；session 文件缺失/坏行 → `truncated:true` 降级页。
- 时序：thread 状态变化（start/resume/stop）写先行——`listActive()` 是恢复链（T2/T4）的输入；快照写失败要阻塞对应 thread 状态确认（宁可慢不可丢恢复依据）。

## 问题域

- 处理：DDL + PRAGMA user_version 迁移；threads/conversations/usage/settings 读写；恢复快照一致性（写后立读）；SessionReader 尾读/截断容忍（仅兜底：重水化首选协议 get_state/get_messages）。
- 不处理：调用时机（T4）；权限规则（hub，经协议）；agentDir 其它文件（hub 管理）；「展开全部」主路径（协议 get_messages）；raw_events 落库（不落，见契约）。

## 并发/一致性预算

- SQLite 写入仅 thread 生命周期事件与用量聚合（低频，单事务即可，无批量缓冲需求）；WAL + synchronous=NORMAL；SessionReader 全程 worker、单次读块 ≤2MB、主进程回调禁 IO；迁移启动同步执行。
