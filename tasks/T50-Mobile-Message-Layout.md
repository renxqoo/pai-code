# 移动端消息列表布局规范（消息流视觉重构）

> 状态：已核销
> 范围：`apps/mobile` 消息列表视觉层（结构语义沿用 T49，不动契约）

## 1. 设计原则（源自参考图 1/2/3）

1. **全平消息流**：消息区内无任何填充容器——过程折叠底、用户卡底、状态行底全部去掉，
   内容直接铺在页面背景上；层级只靠对齐、字重、灰度表达。
2. **单一间距节奏**：所有块间距取自同一节奏表，只用 `marginTop`，禁止上下边距叠加。
3. **正文优先、过程降权**：结果正文是主角（深色、大行距）；过程行是脚注（浅灰、单行）。
4. **工具行文案为主**：绝不露命令行原文 / 绝对路径 / shell 标志；完整命令只在详情弹窗。

## 4. 工具行内容规则（文案为主）

格式：`[图标] [动作动词]  [对象/摘要…]                ›`

| 图标 | 动作 | 示例 |
|------|------|------|
| ✎ | 写入 | `写入  package.json` |
| ✓ | 读取 | `读取  src/store.ts` |
| ▶ | 运行命令 | `运行命令  检查 Node 环境并尝试安装依赖…` |
| ⌕ | 搜索 | `搜索  过程折叠相关组件` |
| ▦ | 并行执行 | `并行执行  3 项工具` |

**不显示**：绝对路径、shell 标志、原始命令串、文件系统前缀。
对象摘要优先用人类描述（fixture 的 title/summary）；无描述时退化为动作 + 对象名，
仍不拼路径。

**详情弹窗**（点击工具行 → 底部 Sheet）：命令原文、输出、耗时、状态——
全 App 唯一展示完整命令的位置。

## 5. 间距节奏表（4px 基准，散乱感的根治点）

| 位置 | 值 |
|------|----|
| 轮 ↔ 轮 | 20 |
| 用户请求 ↔ 过程头 | 12 |
| 过程头 ↔ 过程行 | 2 |
| 过程行 ↔ 过程行 | 0（行高自带，行内 padding 统一 10） |
| 过程 ↔ 结果正文 | 8 |
| Markdown 块 ↔ 块 | 10 |
| 列表项 ↔ 列表项 | 3 |
| 代码块外边距 | 10 |
| 屏幕左右留白 | 16 |

规则：**块间距只挂 `marginTop`，值必须来自本表**；行内元素（图标、文字、箭头）
不产生块间距。

## 7. 去背景区分表

| 位置 | 处理 |
|------|------|
| 过程折叠展开容器 | 去填充（现 surfaceSubtle 底） |
| 用户请求 | 去填充（现任务卡底）→ 右对齐纯文本，靠对齐区分 |
| 思考/工具/状态行 | 去填充，行靠 hover/按压反馈 |
| 行内码 | **保留**极淡 pill（参考图 3 同款，可否决） |
| 代码块 | 去填充，改 1px 发丝边框（可否决，可改纯等宽） |
| 详情弹窗 | 保留 surfaceRaised（浮层必须有底） |

## 8. 折叠交互（沿用 T49 契约）

- 默认：完成/运行收起，失败展开；手动开合优先。
- 头行：状态图标 + 状态文案 + 当前动作/失败原因 + 时长 + chevron；运行中带 spinner。
- 并行工具 ≥2 条折叠为组；组内逐行可点。
- 思考行点击行内展开（限高 200 滚动）；工具行点击开底部详情弹窗。
