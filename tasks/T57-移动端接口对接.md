# T57 移动端接口对接：fixture 原型 → hub 直连

> 状态：定稿
> 级别：大（桌面端新增 mobile-bridge + 移动端传输层/事件映射/store 替换 + 全 UI 接线）
> 范围：`apps/electron`（主进程 bridge）、`packages/contracts`（mobile bridge 帧契约）、`apps/mobile`（传输/映射/store/全部屏接线）

## 1. 现状与目标

**现状（对接前）**：移动端 166 个 TS 文件全是 UI 原型——对话流来自 `fixtures/agent-conversation.ts`，
历史来自 `fixtures/demo-data.ts`，模型清单来自 `strings/zh.ts` 硬编码，零网络层、零 hub 通路。

**目标**：手机 App 与桌面端共享同一 hub（经桌面端 bridge），全部界面真实数据驱动：

- 对话：`session/start|resume|prompt|abort` + `session/entries` 水化 + UiEvent 流式
- 历史：`app/bootstrap.sessions` + `session/listSaved` + `sessionUpdated/Removed` 事件
- 弹窗（权限确认）：`dialogRequest` 事件 + `dialog/respond`
- 模型：`model/list` + `session/setModel`
- 思考/权限档：`session/thinkingLevels|setThinking` + `permission/mode|setMode`
- 会话操作：改名/置顶(本地偏好)/归档(本地偏好)/删除(`session/stop remove`)
- 用量：`session/stats` + `session/tokenAnalytics`
- 上下文占用：`session/tokenAnalytics.utilizationPct`（输入框徽标）
- 断线重连 + 重连后增量水化（`session/entries.since` 游标）

## 2. 架构（通道即角色）

```
手机 App（Expo RN）
  └─ MobileClient（Client 接口实现：invoke/subscribe）
       └─ WebSocket（LAN: 桌面端 IP:8787，配对码 → 令牌）
            └─ 桌面端 mobile-bridge（Electron 主进程）
                 ├─ invoke → 既有 createApiRoutes().invoke（60+ ApiSchemas 全集，zod 校验同门）
                 └─ events → 既有 emitToRenderer 泵（UiEvent 全集，双消费者：IPC 桌面渲染层 + WS 手机）
```

**裁决**：一期 LAN 直连（同 Wi-Fi 场景；与 devices 页「局域网安全配对」文案一致）。
中继（跨网络）不在本期——传输层抽象成 `Client` 接口注入，后续换 URL 即可，UI 零改动。

## 3. 协议（`packages/contracts` 新增 `mobile-bridge.ts`）

WS 上行帧（手机 → 桌面）：
- `{ type: 'pair', code }` → 配对（6 位码，桌面端 UI 展示，TTL 5min，一次性）
- `{ type: 'auth', token }` → 鉴权（成功回 `{ type:'ready', serverInfo }`）
- `{ type: 'invoke', id, method, params }` → API 调用（id 关联响应）
- `{ type: 'ack', seq }` → 事件确认（服务端事件缓冲重发依据）

WS 下行帧（桌面 → 手机）：
- `{ type: 'paired', token, serverInfo }` | `{ type: 'pairFailed', reason }`
- `{ type: 'invokeResult', id, ok, data|error }`（ApiOutcome 直传）
- `{ type: 'event', seq, event }`（UiEvent；手机 ack 后推进水位，重连按 seq 续传）
- `{ type: 'ping' }` / `{ type: 'pong' }`

## 4. 桌面端 mobile-bridge（`apps/electron/src/main/mobile-bridge/`）

- `server.ts`：ws 服务器（node:ws——Electron 主进程可用 node 全集），端口 8787（可配）
- `pairing.ts`：配对码生成/校验/TTL；令牌签发（crypto.randomBytes 32B hex，持久化 `settings.json` 的 `mobileTokens`）
- `session.ts`：WS 会话（鉴权前仅 pair/auth 帧；鉴权后 invoke 路由 + 事件扇出）
- `event-fanout.ts`：事件环形缓冲（上限 2000，ack 水位重发；重连从 watermark 续传）
- 桌面 UI 钩子：`getMobileBridgeState()`（供渲染层展示配对码/已连接设备——本期只留 API，渲染层面板后续任务）
- 安全：令牌常量时间比较；invoke 走既有 zod 校验路由（渲染层 IPC 同门）；bridge 不开公网（bind 0.0.0.0 但令牌门槛——LAN 内其它设备无令牌不可用）；配对码 5 次失败锁 5min

## 5. 移动端（`apps/mobile/src/mobile/`）

- `transport/ws-client.ts`：WS 实现（重连退避 1s→30s；seq 确认；invoke pending 表超时对齐 PC timeouts）
- `transport/client.ts`：`Client` 接口适配（invoke → ws 帧 id 关联；subscribe → 事件帧分发）
- `bridge/pairing.ts`：配对流程（输入码 → paired(token) → 安全存储令牌 expo-secure-store…本期 AsyncStorage+文件，注释留升级位）
- `state/bridge-store.ts`：连接状态（connecting/paired/disconnected）+ serverInfo
- `state/session-sync.ts`：**核心**——UiEvent 流 → `ChatMessage[]` 的归并器
  （turnStarted/userMessage/textDelta/thinkingDelta/messageFinal/toolCall*/turnSettled/dialogRequest/dialogSettled →
  既有 turns.ts 的 TurnView 模型；messageFinal 权威终局替换流式缓冲——与 PC live-controller 同语义）
- `state/history-sync.ts`：bootstrap/listSaved + sessionUpdated/Removed → `ConversationSession[]`
- `state/settings-sync.ts`：model/list + thinkingLevels + permission/mode → 选项面与当前档
- 各屏接线：替换 fixtures import（chat-screen/history-store/workspace-sheet/models/settings/usage）
