# 子代理执行展示对齐（对话流内 task 行）方案

> 状态：已实施（2026-09-10）
> 级别：中（contracts 两视图形状加可选字段；跨 contracts / adapter / renderer 三层）
> 用户指令：参考图样式——对话流中 agent 执行展示为「🤖 子智能体 `Explore` · 分析 pai-cli sandbox 现状」
> 单行：机器人图标 + 粗体标签 + 蓝色等宽 agent 名 + 「·」+ 灰色任务描述。

## 背景与载体裁决

- hub 的 `task` 工具（single `{agent, task}` / parallel `{tasks[]}` / chain `{chain[]}`，
  TaskItem 恒含 agent+task）是子代理派生的唯一入口；其工具调用**在会话转写里有持久记录**
  （assistant 条目的 toolCall），live（toolCallAdded/messageFinal）与水化（get_entries 重建）
  走同一条 args → 预览的通路。
- **载体 = task 工具调用行本身**（`ToolCallRow`，kind=subagent）。不重新引入独立 subagents 轮内块：
  子代理事件（subagentStarted 等）不落转写，独立块在 settle 对账替换 / 历史水化后会消失，
  live 与历史展示不一致——T24 删除流内条的根因即在此，本方案不改该裁决。
- 现状行显示「子代理 + argsPreview（恰好落到 agent 名）」，缺任务描述、无样式分层。

## 契约

- **无 hub 协议变更**。contracts 渲染层视图形状加法（可选字段，旧载荷不含时行为不变）：
  - `ui-events.ts`：新增 `SubagentSpawnViewSchema = { agent: string; task: string }`；
    `ToolCallViewSchema` 增可选 `subagents: SubagentSpawnView[]`。
  - `api.ts`：HistoryItem assistant 条目的 toolCalls 元素增同形可选 `subagents`（水化通路）。
- adapter 新增纯函数 `subagentSpawnsOf(name, args)`：工具名（大小写不敏感）为 `task` 时
  按 single/parallel/chain 统一展开为执行项数组；其余工具、缺字段、垃圾形状返回 `[]`
  （空形态降级）；数组为空时不携带字段（wire 精简）。三处映射点接线：
  - `event-mapper.ts` toolcall_end（toolCallAdded）
  - `event-mapper.ts` message_end（messageFinal.toolCalls）
  - `entries-mapper.ts` assistant 条目（HistoryItem.toolCalls）
- 渲染层 `ToolCallModel` 增必填 `subagents: readonly SubagentSpawnView[]`；
  全部构造点归一（`?? []`）：fold-events（2 处）、hydrate-items（2 处）、demo derive。
- strings：zh `labelSubagent`「子代理」→「子智能体」（对齐参考图文案）；zh 其余「子代理」
  同步统一为「子智能体」（agentsWorking / closeAgents / toggleAgents / agentsPanelEmpty /
  steerPlaceholder ×2 / stopConfirmHint / dialogs.fromSubagent）——同一概念一套说法。
  en 保持 `Subagent` 不变。
- 事件时序：无新增事件；task 行状态仍由主线程 toolEnded 承载（终态最后）。

## 展示规格（参考图对齐）

- kind=subagent 且 `subagents` 非空：**每个 spawn 一行**（parallel/chain 的每个 item 都是一次
  agent 执行）。行结构 = 骑轨状态图标 + 粗体标签「子智能体」+ 蓝色等宽 agent 名
  （`font-mono text-link`）+ 灰色「·」+ 灰色任务描述（`text-muted-foreground`，truncate）。
- 状态语言沿用全应用工具行口径（参考图为运行中截图，全部是 Bot 图标，与我们 running=subagent
  Bot 图标一致；完成/失败仍显绿勾/红叉，不单改为恒 Bot）：running=Bot（shimmer）、ok=勾、
  failed=叉、stopped=减号。
- 行尾状态/耗时/展开箭头挂**最后一行**；详情区（ToolCallDetail）随其展开；每行均可点击
  切换同一展开态。运行中有输出自动展开、失败常开语义不变。
- `subagents` 为空（未知工具形状 / 垃圾参数）→ 退回现状单行渲染（标签 + argsPreview），不崩溃。

## 问题域

- 处理：task 工具调用的对话流行样式对齐参考图；agent 名与任务描述的结构化透传；
  zh 术语统一。
- 不处理（归属）：
  - Agents 面板与输入框徽标（T24 口径）不动——面板仍是子代理内部工具明细 / steer / 汇总入口。
  - 逐 spawn 的独立终态（parallel 中哪个失败）：hub 侧 task 工具单一 toolResult，无 per-spawn
    终态关联，行内共享调用状态；要做需 hub 先行。
  - 后台任务（background:true）完成通知的展示：走既有 task-notification 系统信封，不在本批。
  - `subagentStarted.task` 字段继续被折叠层丢弃（面板不展示任务描述，无需存储）。

## 并发/一致性预算

- 无新增定时器 / IO / 事件；纯派生渲染。spawns 数上界 = hub 预算 ≤8/调用，行渲染 O(spawns)。
- live 与水化同源（都来自 args 的结构化展开），settle 对账替换前后行形态同构，视觉不重排。

## 拆分与实施顺序

1. **M1 契约 + adapter**：contracts 两 schema、`subagent-spawns.ts` 纯函数、三映射点接线、
   adapter 单测（表驱动）。验收：四门。
2. **M2 渲染层**：`thread-model.ts`、构造点归一、`tool-call-row.tsx` 新样式、strings 术语统一、
   组件 / 折叠 / 水化测试。验收：四门 + 全量测试。
3. 对抗审查（独立会话，喂 diff + 方案节选）→ 收口核销。

## 裁决

- 载体 = task 工具调用行（架构必然，见「背景与载体裁决」，非用户分叉）。
- 用户指令：行样式与文案对齐参考图（「子智能体」措辞、蓝色等宽 agent 名、· 分隔、灰色描述）。
- 默认裁决 A：完成/失败态沿用现有状态图标语言（绿勾/红叉），不恒显 Bot——参考图无法证明
  完成态形态，且与全应用工具行一致性优先。否决窗口：交付后可改。
- 默认裁决 B：zh 全量统一「子代理」→「子智能体」（不只行标签）——同一概念一套说法，
  避免一行一词。否决窗口同上。
- 默认裁决 C：parallel/chain 展开为一 spawn 一行（每个 item 就是一次 agent 执行）；
  行尾状态挂最后一行。否决窗口同上。

## 对抗审查处置（独立会话，实现侧逐条处置）

| 发现 | 处置 |
| --- | --- |
| P2-1 空 `tasks`/`chain` 数组与 single 字段并存时与 hub 模式判定分歧（hub 长度>0 才成立，adapter 误判数组模式丢失清单） | 采纳：`spawnItems` 数组分支加 `length > 0` 守卫，空数组回落 single；补症状回归用例 |
| P3-1 `clip` UTF-16 截断可劈开代理对（本次扩大适用面到 agent/task 文本） | 采纳：`clip` 截断点落在高位代理时整体让位；预览域两处消费（argsPreview/subagents）同受益；补回归用例 |
| P3-2 双模式字段并存（如 tasks+agent/task）展示的是「请求」而非「执行」 | 驳回：hub 对该形状直接报 Invalid parameters，调用失败行尾红叉已如实传达；宽容展开属垃圾输入降级语义，已补表驱动用例固化规则 |
| P3-3 tool-call-row stopped 行尾分支无断言；「agent 缺失」用例缺分隔点负向断言 | 采纳：补 stopped 行尾用例、分隔点负向断言、toolLabel 全分支表驱动（read/edit/write/grep/ls/未知工具） |

## 测试口径

- adapter（表驱动）：single / parallel / chain 展开；非 task 工具返回空；缺 agent/task 字段、
  垃圾形状降级；工具名大小写不敏感；空展开不携带字段；三映射点携带断言（event-mapper /
  entries-mapper 既有用例扩断言）。
- 渲染组件（renderToStaticMarkup 静态断言）：单 spawn 行 = 标签 + agent 名 + 描述三段；
  多 spawn 行数与行尾挂最后一行；空 subagents 回退 argsPreview；failed 行尾退出码；
  展开详情可达。
- 折叠 / 水化：subagents 字段透传（fold-events toolCallAdded / hydrate-items assistant）。
- strings：zh 改动由既有引用编译面兜底；无新增 key（仅改值）。
- 分层：单元（adapter + 组件 + fold + hydrate）；无跨进程面 → 不加 e2e。
