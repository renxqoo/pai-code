# ⌘K 全局面板（侧栏搜索退役 + ⌘P 合并） 方案

> 状态：需求定稿 + **对抗审查修订轮已并入**（三路独立审查：契约面 / 运行时行为面 / 删除彻底性面）
> 级别：高
> 波及：渲染层搜索/面板/快捷键/Esc 链 + uiStore 契约收缩 + strings 归位 + 14 个测试文件

## 背景

侧栏搜索与全局命令面板（⌘P）功能重叠且形态割裂：

- 侧栏搜索（`sidebar-search.tsx` + `sidebar-search-input.tsx` + `filter-sessions.ts`）只搜标题/项目名，原地过滤侧栏列表，检索面 2 项
- ⌘P（`palette/command-palette.tsx`）是手搓 overlay（`role="dialog"` + 遮罩 div，`bottom-[28px]` 上弹），检索面 5 组约 11+N+M+K+7 条，其中 sessions 组与侧栏搜索完全重叠

两个后果：① 存在两个「搜会话」入口；② 两条 Esc 裁决路径并存。

更根本的问题：现有两套实现都在搜「用户记得的名字」，而标题是 hub 按首条消息前缀自动命生的摘要，不是用户的记忆线索。用户记得的是「上周那个登录跳转一直报错的会话」，不是「会话 3f2a 叫 修复登录跳转」。

本任务把两者合并为一个全屏 ⌘K 面板，先把检索面统一到一处；正文检索（真正的能力提升）不在本任务，见「不处理什么」。

## 处理什么

1. **⌘K 面板 = 全屏 shadcn `CommandDialog`**（`packages/ui` 已导出，基于 Base UI Dialog + cmdk；`PickerDialog` 已有成熟消费先例）。内容为原 ⌘P 五组：actions / sessions / files / commands / settings，sessions 保持平铺。
2. **⌘P 删除**：快捷键、装配、文案徽标、命名一并撤。
3. **侧栏搜索退役**：内联搜索框、原地过滤、`filtered` 空态全部消失。
4. **侧栏「搜索 ⌘K」入口行保留**，改为打开面板。
5. **Esc 裁决单一化**：`esc-action` 注册表移除 `sidebar-search` 与 `palette` 两层，**新增 `command-panel` 兜底层**（见契约 B1），其余 Esc 交 Base UI Dialog 自管。

### Esc 单裁决的机制（后人勿静默破坏）

正常 Esc 路径干净，依赖三件事，**任一被改都会静默打破单裁决**：

1. Base UI `useDismiss.mjs:458` 把 Escape 监听挂在 `document` 冒泡阶段，早于 `use-esc-dismiss.ts:89` 的 `window` 监听
2. `:108-110` 在正常路径执行 `event.stopPropagation()` → 事件止于 document，到不了 window
3. `escapeKeyBubbles` 默认 `false`（`:24`）

**但 IME 合成期是例外**：`useDismiss.mjs:96-98` 在 `isComposingRef` 为真时**提前 return，不执行 stopPropagation** → 事件继续冒泡到 window → 若注册表不认识面板，`generating` 为真时 `escActionFor` 返回 `stop-turn`，**中文输入法选词时按 Esc 会停掉正在跑的那一轮**。

故注册表**不是删层，而是新增兜底层**：`{ id: 'command-panel', isOpen: panelOpen, action: { kind: 'none' } }`。正常路径不触发它（已被 stopPropagation 掐断），泄漏路径由它吸收。

**注册表变更：8 层 → 7 层**（删 `palette`、`sidebar-search`；加 `command-panel`）。删除后次序为：`local-dialog → command-panel → usage → new-task → settings → project-files → panel`。`project-files < panel` 与 `local-dialog` 首位均保持不变（已核对）。

### 检索面（`palette-items.ts` 封闭词表，五组）

| 组 | 内容 | 匹配面 | 选中行为 |
| --- | --- | --- | --- |
| actions | 11 项动作（7 固定 + 4 条件：有 cwd 出本机打开/复制路径，有会话出复制 ID/关闭） | 动作名 | 立即执行 |
| sessions | 全部会话，按 `lastActivityAt` 倒序 | 标题 + 项目名 | 跳转该会话 |
| files | 活跃会话 cwd 下的文件，≥1 字符触发 | 完整路径 | 打开文件 tab |
| commands | hub 提供的斜杠命令 | 名称 + 描述 | 填入 composer 草稿（**不执行**） |
| settings | 7 个固定分区 | 分区标题 | 打开设置到该分区 |

匹配机制：cmdk 模糊匹配 `value`(=item.id) + `keywords`(=label + detail)，故搜线程 id 也能命中会话条目。

## 不处理什么（归属写明）

- **会话消息正文检索**：需要 WAL 侧索引（WAL 是唯一真相，索引为可重建派生物，带 `indexed_seq` 水位线），属独立立项。中英文 FTS5 行为已在 Electron 44.2.0 / Node 24.20.0 / SQLite 3.53.4 实测：`node:sqlite` 自带 FTS5 零新增依赖，但默认 `unicode61` 对中文**完全不可用**（CJK 不分词，子串 0 命中）；`trigram` 3 字以上可用但**2 字是硬下限**；**字间插空格 + phrase 查询**两字与英文混排均可命中，是选型结论。
- **移动端历史搜索**：`apps/mobile` 独立端，本次不动。
- **`packages/ui` 的 `CommandDialog` 本身**：已存在且经 `PickerDialog` 验证，不改（「先关后派」的顺序调整在消费侧完成，无需改包）。
- **sessions 组分组**：保持平铺（用户裁决）。

## 挂账

- **正文检索**：需 WAL 侧可重建索引 + `session/search` 协议 + 本仓 `packages/contracts` 镜像。hub 有脚本形态与 `bun build --compile` 单文件形态两种执行方式，索引驱动须用 `bun:sqlite`（不可照抄 driver 侧的 `node:sqlite`）
- **文件搜索作用域**：现绑死 `activeThreadId` 的 cwd，切会话即变——搜索结果不应随当前查看的线程变化，应显式可切作用域
- **`local-dialog` 层疑似死层**：`esc-action.ts:58` 的新建任务页 WorkspacePickerDialog 走 Base UI，同样被 stopPropagation 保护。顺带核实后可删
- **历史 task 文档不回改**：T11/T17/T18/T30/T32 是已核销任务的事实快照，按仓库纪律版本差异只属 log 文档。**但 T60 追加反向指针**：本任务取代 `T32 §3.1-11` 门控矩阵与 `T32:151` Esc 链序表述——`T32:160` 写明「⌘P 独立门控」，若被后续 agent 当现行规格读，会实现出一个已删除的门控。零改动历史文件即可消歧。
