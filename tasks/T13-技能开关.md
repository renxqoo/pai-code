# 技能开关（用户级技能禁用） 方案
> 状态：已实施（对抗审查 8 项处置完毕）
> 级别：中

## 背景与机制（已核实）

- Pai 会话的用户级技能来源两处：`agentDir/skills/`（= userData/agent/skills）与 `~/.agents/skills/`（pi 的 agents 形态）；均不受 trusted 限制自动加载。
- pi 的启停真相 = `agentDir/settings.json` 的 `skills` 数组（globalSettings.skills，override 模式）：`-名字` = 强制禁用（优先级最高）、`!名字` = 排除、`+名字` = 强制启用；缺失/空数组 = 全启用。会话创建时读入。
- 架构裁决 D6（electron-integration.md）：settings.json 单一写入者 = Electron，hub 只读 → **Pai 主进程写该文件即合法通路，无需 hub 新协议**。

## 契约

- `skills/list`（空参）→ `Array<{ name: string; description: string | null; enabled: boolean; origin: 'agent' | 'agents' }>`
  - 全集 = 两处用户级技能目录扫描（子目录含 SKILL.md 才计入）；description 取 SKILL.md frontmatter（缺失 null）；enabled 按 pi override 语义计算（Pai 只消费「精确名匹配」子集）。
- `skills/setEnabled` `{ name: string; enabled: boolean }` → 同 list（写 agentDir/settings.json 后的新清单）
  - 写语义：disable → 追加 `-name`；enable → 移除 `-name` 与 `!name` 精确条目；文件其余键原样保留（读-改-写）；坏/缺文件按 `{}` 起步。
  - 失败形态：`write_failed`；未知技能名 `skill_not_found`。
- 生效时序：设置保存成功后，渲染层对全部 live 会话逐个重开（stop → 同文件 resume，复用受信重开机制）→ 新会话读新 settings，被禁技能不再加载。

## 问题域

- 处理：用户级技能的枚举（含禁用态）、启用/禁用落盘、生效编排（重开活跃会话）。
- 不处理：
  - 项目级技能（受信 .pi/.agents 面板）——会话维度，留档后续；
  - pi 完整 pattern 引擎（glob/路径形态）——Pai 只生成/消费精确名条目，手写复杂条目原样保留不覆盖；
  - 会话运行中热重载资源——hub 无该命令（hub 缺口留档：N 系列候选「资源重载命令」）。

## 并发/一致性预算

- settings.json 原子写（agent-dir-files 既有路径，随机 tmp + rename + fsync）；
- 开关操作串行化：主进程在途写未完成时再次调用直接返回当前清单（单飞不排队，UI 快速点击不叠加写）；
- 会话重开逐个串行（每会话 stop 等 ack 再 resume），失败保留原会话并 notice。

## 拆分

- `packages/contracts`：两个 API schema + SkillView。
- `apps/electron/src/main/agent-dir-files.ts`：白名单 + `settings.json`。
- `apps/electron/src/main/skills-inventory.ts`（新）：目录扫描、frontmatter 描述提取、pi skills override 的宽容解析与精确名判定、toggle 条目增删（全纯函数 + fs 注入）。
- `apps/electron/src/main/api-routes.ts`：两路由；主进程单飞标志。
- 渲染层：store/controller 增 skills 状态与动作；设置页技能卡加开关（Base UI Switch 封装进 packages/ui）；生效编排（重开 live 会话）。
- strings zh/en。

## 裁决

- **默认裁决（否决窗口）**：开关保存后自动重开全部活跃会话（贴合「关闭后会话中就无法使用」的预期；重开会换 threadId，历史保留）；若不想自动重开，改为提示手动重开。
- 禁用条目固定写 `-name`（pi 语义优先级最高的强制排除）；启用时同时移除 `-name`/`!name` 精确条目。
- 技能名冲突（两处同名）：一并生效（pi 语义本就按名排除两处）。

## 对抗审查处置（已实施轮）

- **P0 修复（既有缺陷一并根治）**：hub 协议 resume 缺省 trusted=false——重开会话不传 trusted 会把受信会话静默降级，且应用重启的 resumeAll 同病。根修：注册表行增 trusted 列（sqlite ALTER 迁移 + COALESCE 保留），session/resume 不带 trusted 时主进程按注册表补全，start/resume/恢复链全程记录与回放。
- P1×3 修复：技能开关编排链式排队（防多次开关的重开循环交错）；清单扫描对齐 pi 语义（跳点目录/node_modules、父目录无 SKILL.md 递归下钻、跟随符号链接、嵌套技能名=相对路径）；启停判定对齐 pi 优先级（! 排除 → + 复活 → - 击杀）并归一 ./ 前缀。
- P2 修复：删除主进程假单飞（同步路由体天然串行）；刷新入口常显；空态文案改「未安装用户级技能」；skillsHint 明示重开会中断进行中的生成。
- 已知限制（留档）：手写 glob/绝对路径 override 条目的禁用态 Pai 显示为启用（判定只认精确条目子集）；根级散装 .md 技能形态不扫描；pi settings 单写者不变量依赖「hub 命令面不写 settings」（受信项目扩展可触发 pi 侧写，属 hub 缺口，并入 N 系列推动）；重开换 threadId 丢按键隔离的输入草稿（低频接受，文案已提示中断）。
