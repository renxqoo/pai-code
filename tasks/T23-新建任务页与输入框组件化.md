# 新建任务整页 + 输入框组件化 方案

> 状态：已实施（待核销）
> 级别：中
> 参考稿：ZCode 形态新建任务页（问候语 + 项目/分支条 + 白卡输入框 + 快捷任务胶囊）
> 用户裁决：① UI 布局对齐参考稿、风格保持 shadcn；② 输入框必须组件化（线程页与新任务页共用同一套）；③ git 能力要真实可用（非假数据）。
> 方法论：主体走 feature-dev-v2；步骤 2（组件化拆分）借用 repo-migration-e2e-v2 的「旧实现审计 + 行为映射 + 旧测试当规格 + 对照旧实现审查」纪律。

## 契约

- 新 API `'git/branches'`：
  - params：`{ cwd: z.string().min(1) }`（`.strict()`）
  - result：`{ isRepo: boolean; current: string | null; branches: string[] }`——分支名去重升序；非 git 仓库返回 `isRepo:false` + `current:null` + `branches:[]`（空形态降级，不报错）
  - 失败面：沿用 `{ok:false,reason}`；`cwd_not_allowed`（不在已知项目目录白名单）/ `cwd_not_found`（目录不存在）/ `git_unavailable`（git 进程无法启动）/ `git_failed:timeout` / `git_failed:output_too_large` / `git_failed:<首行摘要>`
- 新 API `'git/checkout'`：
  - params：`{ cwd: z.string().min(1); branch: z.string().min(1); create: z.boolean().default(false) }`（`.strict()`）
  - result：`{ branch: string }`——成功即「当前 HEAD 已指向该分支」（非选项形、非路径形）
  - 失败面：`cwd_not_allowed` / `cwd_not_found` / `not_a_repo` / `unknown_branch` / `branch_exists` / `dirty_worktree` / `invalid_branch`（选项形/非法 ref 名，先于 git 拦住）/ `git_unavailable` / `git_failed:timeout` / `git_failed:output_too_large` / `git_failed:<摘要>`
  - **仓库可执行面隔离**：所有 git 子进程带 `-c core.hooksPath=/dev/null -c core.fsmonitor=false`——仓库本地 config 的 hooks/fsmonitor 都指向可执行文件，恶意仓库（如克隆来的）能让「切分支」在 main 进程全权限下跑代码（绕开 hub 沙箱与 `trusted:false`）；`-c` 必须在子命令之前
  - **分支名门禁**：`isValidBranchName`（git check-ref-format 规则子集）在 create 与 switch 两路都先于 git 执行——`git checkout --detach`/`-f` 这类「退出码 0 但改变 HEAD」的选项形不得被报成成功；列表侧同样过滤（`for-each-ref` 能列出 `update-ref` 造出的 `refs/heads/-f`）
- 契约类型单一真相：`GitBranchesViewSchema` 导出在 `packages/contracts/src/api.ts`，主进程 `git-branches.ts` 直接 `import type { GitBranchesView }`（不各自定义）
- **零 hub 协议变更**：git 能力全部在 Pai 主进程侧（`child_process.execFile('git')`，无 shell），不经 hub；新会话初始模型/思考档/权限模式复用既有 `thread/start`（provider/modelId）与 `set_thinking_level`、会话 sidecar 命令
- 渲染层 `createSession` 签名（渲染层内部动作面，非契约）：
  `createSession(input: { cwd: string; trusted?: boolean; model?: string; thinkingLevel?: string; permissionMode?: PermissionRules['mode'] })`
  —— `model` 为 `provider/modelId` 串；`thinkingLevel`/`permissionMode` 在 `thread/start` 成功后按 threadId 后置应用（思考档 `session/setThinking`、权限模式以全局规则为基线写 sidecar；全局规则未加载时跳过，不臆造基线）
- 新渲染层动作：`startTask`（建会话 + 投首条消息，返回 threadId 与 sendFailed）、`defaultModelFor(cwd)`、`searchFilesIn(cwd, query)`、`listGitBranches(cwd)`、`checkoutGitBranch(cwd, branch, create)`
- strings 新 key（中英同步）：新建任务页（问候语四时段、副标题、快捷任务 4 条、项目/分支条无障碍名、工作区选择弹窗标题/搜索/打开文件夹/信任开关、分支选择弹窗标题/搜索/创建并检出、创建分支弹窗标题/输入占位/按钮、非 git 仓库提示、分支失败文案表）；删除 `newThread.{title,hint,fieldCwd,knownDirs,browse}` 与 `composer.{localCheckout,checkoutMenu}`（假数据）

## 问题域

- 处理：
  - **新任务整页**：`NewThreadModal`（弹窗）→ `NewTaskScreen`（右侧主区整页，侧栏不动），侧栏「新建任务」/项目行「新建任务」/⌘N 同入口；Esc 返回（`close-new-task` 语义）
  - **布局对齐参考稿**：水印 → 问候语（本地时段四段：夜/早/午/晚）→ 项目/分支灰底条（位于白卡上方、白卡压住其下圆角）→ 白卡输入框（占位文案 + 底行动作行）→ 4 个快捷任务胶囊
  - **输入框组件化**：`composer.tsx` 拆为 `PromptCard`（白卡壳：form/圆角阴影焦点态 + 附件态与提交编排 + 排队堆 + 隐藏 file input + 底行插槽）/ `PromptInputArea`（textarea + 高亮镜像 + `@`/`/` 补全 + caret/键盘状态机）/ `PromptContextBar`（项目/分支两段，只读与可切两形态）；线程页与新任务页共用
  - **底行动作行布局对齐参考稿**：左侧 `+`（附件）+ 权限模式；右侧 压缩 / 用量环 / 模型 / 思考档 / 发送（生成中为停止）
  - **项目选择**：已知项目目录（活跃会话 + 已保存会话 cwd 去重，最近优先）+「打开文件夹…」走系统选择器；选择弹窗内信任开关（初值 `preferences.trustedDefault`）
  - **分支选择**：真实 git 分支列表 + 切换 +「创建并检出…」（二次小弹窗输入新分支名）；非 git 目录显示「非 git 仓库」且分支段不可点
  - **快捷胶囊**：点击预填提示词到输入框并聚焦（不自动发送）
  - **线程页分支段**：只读展示真实当前分支（任一处 checkout 成功后经 revision 失效信号重拉）
- 不处理（挂账，显式不渲染，不留 noop 控件）：
  - **远程连接工作区**、**「不在项目中工作」**：前者无协议面（hub 只有本地 spawn），后者无 cwd 数据面（`thread/start` 强制 cwd；不引入 homeDir 伪工作区）
  - **Git 图谱**：需要提交历史/图布局数据面，本任务不建
  - **新任务页的思考档 / 用量环 / 压缩键**：三者都是会话级数据面（`get_thinking_levels` 需 threadId；用量来自 `message_end` usage），会话未创建时无真相——不渲染假控件，创建后在会话操作栏调整
  - 分支 ahead/behind 徽标、远程分支分组、分支重命名/删除
  - 项目级 trusted 记忆（沿用偏好默认 + 本次选择；会话建立后仍可在会话菜单切换信任态）
  - 新任务页的斜杠命令补全（无会话即无命令目录；仅保留 @ 文件补全）
  - 线程页运行中切分支（工作树基线会变，风险面大；仅新任务页可切）
  - **`session/start` 无 cwd 门禁（既有洞，非本任务引入，登记挂账）**：`git/*` 的 `cwd_not_allowed` 只覆盖「本应用已知目录」，而已知目录集合由 `session/start` 决定，该命令仅校验 `z.string().min(1)`。威胁模型下（被攻陷渲染层）可先 `session/start` 任意目录再 `git/checkout` 写其工作树。修法需要把 `session/start` 一并门禁到「注册表已知目录 + 系统选择器选过的目录」，但引导页的工作目录是手输文本（无选择器入口），一并门禁会打断首次运行——属跨任务的 API 面加固（api-routes 注释里的承诺目前强于实际保证），归 T7/T9 后续波次；本任务不半修。缓解事实：渲染层本身已被授予 `session/bash`、`permission/write` 等高权面，`git/checkout` 未新增质变攻击面。
  - git 进程被外部信号（SIGKILL/OOM）杀死与超时无法区分，统一归 `git_failed:timeout`；超时 SIGTERM 后可能残留 `index.lock`（git 下次操作自行报错提示），不做自动清理

## 并发/一致性预算

- git 子进程：`execFile`（无 shell）+ 仓库可执行面隔离（hooks/fsmonitor）+ 5s 超时 + 1MiB 输出上限，覆盖全部调用路径；进程级异常（超时/输出超限/启动失败/目录不存在）与 stderr 分类分开，超时不误报成 `git_unavailable`
- 列表单飞：同 cwd 在途请求复用；**checkout 成功后失效该 cwd 的在途缓存**（否则紧随的刷新会复用切换前快照，界面停在旧分支）
- checkout 全局串行（跨 cwd 也串行：不同 cwd 可能指向同一仓库，宁可过度串行也不并发写工作树）；渲染层另有同步 ref 闸（连按 Enter/双击不双发）
- 渲染层序号守卫丢弃过期响应；`refresh` 读最新 cwd（它在 await 之后调用，不得把旧目录刷回前台）；结算键含 cwd+revision（外部失效重拉期间回到 loading，不留旧分支名无提示）；`revision` 失效信号让线程页只读分支段跟上别处的 checkout
- `@` 补全的请求去重键含搜索上下文（目录），换上下文同时清结果与去重记忆：换目录后同 query 必须重拉（否则会把上一个项目的文件列进消息；A→B→A 快速折返也会因旧键命中而永不重拉）
- 分支列表随 cwd 变化重拉；项目/分支/信任选择态是页面局部 state，不入 store（无跨页真相）
- 无新增 hub 命令，无新增定时器；问候语在打开时按本地小时算一次（不挂 tick）

## 测试口径

- 契约：两方法 params 合法/缺参/空串/未知键拒绝、`create` 缺省 false；result 形状（空形态、分支数组、多余键拒绝）
- `git-branches` 纯函数：`parseBranchList` 去重升序/空输出/非法名过滤；`isValidBranchName` 合法与非法矩阵（含 `HEAD`）；`classifyGitExecError` 三态（真子进程实测形状）；`mapGitFailure` stderr 分类与未知透传
- `git-branches` 行为（fake exec）：进程级异常四态（timeout / output_too_large / spawn_failed / cwd_missing）、非零退出、同 cwd 在途复用、checkout 后缓存失效、跨 cwd 全局串行、创建并检出、脏工作区拒绝、非法分支名不发命令
- 真 git 隔离世界（临时仓库 + 真二进制 + 全真装配）：列表/切分支/创建并检出/同名拒绝/脏工作区拒绝且改动未丢/选项形 ref 不进列表也不可检出/**恶意仓库 hooks+fsmonitor 不被执行（对照组 + 处理组）**
- 渲染层纯函数：`greetingKeyOf` 边界、`branchSegmentOf` 五态、`parseModelKey`、`workspaceItems`/`quickTaskItems`/`greetingTexts`、`git-actions` 三动作的早退与透传
- 控制器：`createSession` 选项化（后置命令顺序、以全局规则为基线的 sidecar、不传则不多发、start 失败透传）
- 组件（仓库静态口径：`renderToStaticMarkup` 冒烟 + 纯函数承载逻辑；无 DOM 交互装置，交互走真机走查）：`PromptCard` 插槽/排队堆/隐藏 file input/附件选择入口；`PromptContextBar` 只读/可切/任一段缺省三态；`ComposerActionsRow` 有会话/无会话两组控件；`NewTaskScreen` 时段问候/胶囊/无假控件/权限开关；`newTask.branchFailed` 文案表逐 reason
- 表驱动：分支选择参数矩阵（仓库/非仓库/加载中/切换失败）由 `branchSegmentOf` + `BranchPickerDialog` 空态文案覆盖
- 覆盖盲区（如实登记）：`useGitBranches` 与页面交互（点击/键盘）无 DOM 装置，只由真机走查覆盖——引入 DOM 测试装置属 T9 装置任务
