# 并行工具执行分组展示（PC 对话列表）

> 状态：已核销
> 级别：中（渲染层增强 + 契约新增可选字段贯通两条数据路径）
> 范围：`apps/electron` 渲染层 thread 目录 + `packages/contracts` / `packages/api` 视图层

## 1. 契约

分组（渲染层纯派生，块模型不动）：

- `toolGroupBuckets(calls)` / `toolGroupLabel(calls)`：并行批次 → 有序类别桶与人话标题
  （桶序固定：编辑 → 阅读 → 搜索 → 目录 → 命令 → 子智能体 → 未知；标题不带计数）。
- `toolGroupStatus(calls)`：批次聚合态（失败 > 运行中 > 停止 > 成功）。
- `toolGroupIsParallel(calls)`：≥2 个调用才算并行批次（单调用不套组头）。
- `toolGroupIcon(calls)` / `toolRowIcon(name)`：类别图标（编辑类铅笔、阅读书、命令终端、其余扳手）。
- `toolRowLabel(name, status)`：单条执行行的动作短语（终态过去式「已阅读文件」，运行中现在进行时
  「正在阅读文件」；未知工具直呼原名）。
- `autoOpenForGroup(calls)`：批次组开合的自动策略（任一失败常开）。
- `chevronRevealClass(open)`：收起态箭头 hover/聚焦显形、展开态常显（单一真相）。
- 组件：`ToolGroup`（持有开合状态）/ `ToolGroupHeader`（标题行）/ `ProcessRailIcon`（行内图标位，
  思考、组头、单条行共用同一形态）/ `ToolsBlock`（单调用直出行、并行套组头）。

编辑/阅读详情（契约新增可选字段，贯通两条数据路径）：

- `contracts/ui-events.ts`：新增 `EditHunkViewSchema` = `{oldText, newText}`；
  `ToolCallView.editHunks?`（可选，缺席 = 非编辑工具）。
- `contracts/api.ts`：`HistoryItem.assistant.toolCalls[].editHunks?`。
- `contracts/inflight-views.ts`：`InflightMessageView.toolCalls[].editHunks?`。
- `api/views/edit-hunks.ts`：`editHunksOf` / `editHunksField`——edit 工具入参
  `{path, edits:[{oldText,newText}]}` → 片段对；空则不携带字段（与 `subagentsField` 同一约定）。
- 贯通点：`event-mapper`（live 侧 `toolCallAdded`）、`entries-mapper`（转写重建
  `assistant/message` 与 `tool/call` 补面、`tool/result` 透传）。
- 渲染：`ToolCallDetail` 按种类分派——read 走 `FileContentPanel`（行号列 + 内容），
  edit 走 `EditHunkList`（红删/绿增的补丁片段，不是整个文件），其余走 `OutputPanel`。

## 2. 问题域

处理：并行批次的组头聚合与开合、组头文案合成、组头/执行行灰度、箭头悬停显形、
执行行的图标与状态短语、按工具种类分派的详情区（阅读内容面板 / 编辑补丁面板 / 通用输出面板）。

不处理：正文与思考块的展示（各自独立呈现，不进入组折叠）；轮级「已工作」状态行与整轮折叠
（`TurnStatusLine` / `useTurnCollapse` / `visibleTurnBlocks` 原样保留）；思考块灰度与图标语义
（保持现状）；write 的行级补丁（整文件重写无基线可比，只走行数统计与输出面板）；
协议事件形状与 hub 侧工具实现。

## 3. 裁决

- **用户裁决 1**：并行调用合并成一行可开合标题；标题分档——都是命令「运行了命令」、
  都是编辑「编辑了文件」、编辑+命令「编辑了文件运行了命令」、都是阅读「阅读了文件」；
  混合执行文案由实现方合成（固定桶序动宾流水，>3 类以「等」收口）。
- **用户裁决 2**：展开/收起箭头 hover 才显形；展开态常显，只有收起态是 hover 交互。
- **用户裁决 3**：工具执行行与组头标题统一灰色；每条执行行带「已…」状态前缀。
- **用户裁决 4**：正文与思考独立展示，不与工具执行一起折叠、不灰化（思考灰度维持现状）。
- **用户裁决 5**：轮级「已工作」头部功能不改。
- **用户裁决 6**：单条执行（无并行可合并）也带行首图标——图标语义属于执行单元本身。
- **用户裁决 7**：查看文件与编辑文件各自有展开详情：查看走文件内容面板，编辑走 diff
  （只展示改动片段，不展示整个文件）。
- **用户裁决 8**：文案与图标间距收紧，过程行与正文左对齐（取消左侧竖轨缩进），
  过程行上下间距收小。
- 标题不带计数（默认裁决）：执行过程是脚注，标题从简；要看多少次由展开后的调用行承担。
- 计数/编辑片段上界（默认裁决）：片段单条 2000 字符、每次调用 8 条——参数数组无界，展示面需封顶。
- 组头默认收起、组内有失败时自动展开（默认裁决，与调用级 `autoOpenForCall` 同一裁决）。

## 5. 测试口径

- 文案合成表驱动：全命令 / 全编辑 / 全阅读 / 编辑+命令（逐字断言用户指定文案）/
  三类混合固定序 / 超三类收口 / 未知工具去重 / 空输入降级；桶序与调用到达序无关。
- 聚合态表驱动：失败优先于运行中、运行中优先于停止、全成功、空输入降级。
- 编辑片段表驱动：正常形状 / 大小写不敏感 / 非 edit 工具 / 垃圾形状 / 无改动配对丢弃 /
  片段数上界 / 超长截断不劈代理对；贯通断言（live `toolCallAdded` 与转写两条路径）。
- 详情区分派：read 走内容面板（有行号列、不挂输出面板头）、edit 走补丁（红绿对照）、
  bash 走输出面板、无详情时不渲染空壳。
- 组件：单调用不套组头；并行收起态调用行不进 DOM；组头 `aria-expanded` 点击往返；
  灰度类；收起态箭头 hover 显形、展开态常显。
- 回归：既有 thread / live / api 全量重跑；发现存量缺陷（`tool/result` 重建调用时丢
  `editHunks`）当场修 + 回归用例。
