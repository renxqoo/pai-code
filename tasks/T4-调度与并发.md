# T4 · 线程调度与预算（ThreadManager / StreamAggregator / BudgetTracker） 方案

> 状态：草稿（待评审定稿）｜ 级别：中 ｜ 波次：2（对 Port/mock 可与波次 1 并行开工） ｜ 依赖：T0；联调 T1（映射/编码）、T2（AgentHostPort）、T5（StorePort） ｜ 被依赖：T6/T7/T8（事件流与 API）
> 方案依据：方案第 2、6 章

## 契约

```typescript
// packages/core —— 全部走 Port 注入（AgentHostPort/StorePort/VisibilityProvider）
startThread(args: {conversationId, cwd, model?, trusted?}): Promise<{threadId, status: 'started'|'queued'|'rejected', reason?}>
resumeThread(threadId, continuePrompt?): Promise<同上>          // 转发 hub thread/resume；sessionPath 从 StorePort 取
stopThread(threadId) / steer(threadId, msg): Promise<'steered'|'buffered'|'not_found'> / abort(threadId)
pauseQueue() / resumeQueue()                                     // 预算熔断闸
onInternalEvent(threadId, e: InternalEvent)                      // BudgetTracker/对话框桥接线点
onHubExit(report)                                                // 编排 T2 恢复原语：重启 1 次 + resumeAll，再败标 interrupted
// StreamAggregator：全局单 50ms 定时器、按 threadId 分桶、chunk 聚合、非 chunk 立即冲刷保序、单调 seq
```

- 事件时序硬约定：一次性终态（stopped/crashed/interrupted/rejected）恰好一次；排队位置合并单条广播。
- 错误形态：hub failure response 透传为 rejected/failed + 英文 reason（session_busy/unknown_thread/budget…）；内部异步链全部 .catch 落日志，无 unhandledRejection。

## 问题域

- 处理：thread 生命周期与 conversation 映射；**客户端限流**（全局动态 2..8、单对话 ≤3、排队公平/可见优先/阻塞跳过/扫描预算）；steer/排队缓冲；hub 崩溃/挂死后的恢复编排（调 T2 原语 + 快照重放）；StreamAggregator；BudgetTracker（message_end usage 累计、日界、熔断闩锁、设置热读）；usage 与 thread 状态落库时机（经 StorePort）。
- 不处理：进程语义（T2）；帧解析（T1）；落库实现（T5）；对话框（T6）；IPC/装配（T7）。

## 并发/一致性预算

- 全局活跃 ≤ clamp(物理内存 ÷ 实测单 thread RSS, 2, 8)（启动默认 4，Spike 4 校准）；单对话 ≤3；
- StreamAggregator：定时器恰 1 个（50ms），每桶 ≤200 条/批；drainQueue 每轮扫描预算 = 队列长；终态事件恰好一次（幂等闩）。

## 裁决

- resumeThread 默认不补发 continuePrompt：沿用既有裁决（否决窗口保持）。
- steer 对 queued thread 缓冲补发：既有裁决。

## 测试口径

- 契约断言：startThread 返回判别联合穷举；steer 三形态；终态恰好一次（共享断言助手）。
- 边界/竞态：空队列 drain；stop 不存在 id；resume 查无记录；并发 start 8 路；恢复与手动 stop 竞速；hub exit 与 drain 交错。
- 表驱动：调度优先级矩阵、Budget 事件序列表、恢复场景表。
- 分层：单元（全 mock）+ integration（真 hub 恢复链，T9 夜间门）；UI 串线由 T9 E2E 覆盖。
