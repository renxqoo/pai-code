# T16 · 启动懒恢复（对账占位 + 会话按需 resume） 方案

> 状态：定稿
> 级别：中（模板 B）
> 动机：启动串行全量 resume 使首屏随会话数线性劣化（N × worker respawn ≈ 0.3–1s，>32 会话触发 host 并发上限，每 live worker ≈ 110MB；闲置收编后大部分退回 parked，启动成本白付）。改为「启动只对账渲染占位，会话被使用时才恢复」。

## 契约

- **hub 协议零改动**。只使用既有命令：`thread/list_saved`（host 本地，按 cwd 过滤）、`thread/resume`、`thread/stop`（幂等）。
- **PaiRuntime 接口**：`refreshSessionsFromHost()` 更名 `reconcileSessions()`（语义收窄：只对账，不 resume）；`resumeAll` 删除（onRestart 钩子改挂 reconcile）。无兼容别名。
- **启动时序**：spawn host → ready → `reconcileSessions()`（毫秒级 host 本地命令）→ `app/bootstrap` 即回全部会话（盘上存在的注册表行 = `state:'parked'` 占位视图）。
- **懒恢复时序**：会话被激活（侧栏点击 / bootstrap 自动选中的首个会话 / host 重启后活跃会话收到 parked 视图）或活跃会话发消息 → 至多一次 `session/resume` → 主进程 `applyStartOutcome` 推 `sessionUpdated`（live）→ 渲染层以**响应 threadId** 激活并水化（`get_entries` 首屏，既有通路）。resume 失败不自动重试；用户再次点击即手动重试。
- **错误形态**：resume 失败 → 通知条（`copy.flow.resumeFailed`，文案进 strings）；占位保留不删行。对账时文件确认缺失（该 cwd 的 `list_saved` 成功且不含此路径）→ 删注册表行 + `sessionRemoved`（与既有 resumeAll 的 not-found 删行语义一致，判定提前到对账）。

## 问题域

- 处理：启动/重启后注册表 vs 盘上会话对账；parked 占位视图渲染；按需 resume（去重、threadId 回写、失败面）；resume 路由保留注册表标题 + id 变化旧行替换。
- 不处理：
  - hub 侧任何改动（含闲置收编/预热——hub 自身 15 分钟收编已覆盖，预热默认不开，见裁决）；
  - 会话文件损坏的修复 UI（resume 失败 → 通知条 + 占位保留，用户从 History/文件管理器自行处理）；
  - fork/clone 旧行替换（既有行为，另行任务；本任务只在 resume 路径处理 id 变化）；
  - parked 占位展示磁盘元数据（messageCount/modifiedAt）——侧栏渲染只需注册表 title/updatedAt，不引入第二真相源；
  - History（list_saved）列表本身的聚合逻辑（`savedAcrossCwds` 既有实现不变）。

## 并发/一致性预算

- 启动路径 host 命令数：**0 个 `thread/resume`**；`thread/list_saved` ≤ 注册表去重 cwd 数（host 本地，毫秒级）；`thread/list` 从启动路径删除（新 spawn 的 host 恒空表；host 内不可能存在 Pai 未落的线程——所有线程源于 Pai 发出的 start/resume/fork/clone，均经 `applyStartOutcome` 入表）。
- 懒恢复：每 sessionPath **至多 1 个在途 resume**（渲染层 waking 表去重；hub 对同文件重复 resume 回 failure「already open」）；完成即清登记，失败不自动重试。
- 启动 bootstrap 不再随会话数增长（原 O(N) 串行 resume → O(1) 本地对账）；启动 worker 内存 0（原 N × ≈110MB）。
- threadId 单向真相：窗口/注册表只信 resume 响应 id；id 变化时旧行删除 + `sessionRemoved`，新行落库（既有 resumeAll 不变量的懒化迁移）。

## 拆分

- **主进程** `apps/electron/src/main/pai-runtime.ts`：`reconcileSessions()`（注册表 vs `list_saved` 按 cwd 聚合；null 路径行清理；占位 upsert；确认缺失删行）；`PaiRuntimeDeps` 增 `createHost?`（host 工厂注入缝，测试用，缺省 infra 实现）；删除 `resumeAll`/`sessionFromStartOutcome`/`registryViews`（死代码）。
- **主进程** `apps/electron/src/main/api-routes.ts`：`session/resume` 路由补注册表标题保留（现状抹成 defaultTitle，属存量缺陷顺带根治）与 id 变化旧行删除。
- **渲染层** `live/live-controller.ts`：`ensureLiveSession(threadId)`（parked 判定 + waking 去重 + 激活）；`start()` bootstrap 自动唤醒首个会话；`sessionUpdated(parked,活跃)` 事件触发自动唤醒（host 重启后）；`openSavedSession` 同路径已 live 直接激活。
- **渲染层** `live/workspace-actions.ts`：`selectSession` parked 门；`submitDraft` 发消息前兜底 ensureLive。
- **渲染层** `live/use-live-workspace.ts`：会话激活 effect 增 `activeSession.state` 依赖（parked→live 翻转重拉 hydrate/档位/命令/规则/stats；parked 时早退不发注定失败的请求）。
- **渲染层** `live/store.ts`：`pushNotice` 收为 store 动作（controller 层可发通知，单一真相）。
- **strings** zh/en：`flow.resumeFailed`。
- contracts：零改动（`SessionView.state` 已含 `parked`；`PaiCommandType` 已含 `thread/list_saved`）。

## 裁决

- **用户裁决**：启动只对账渲染；聚焦/使用时恢复；去重必须；失败不自动重试（手动重试=再点一次）；threadId 只信响应；默认不预热（若产品坚持预热：有界并发 3–4、只预热最近 3–5 个，另立任务）。
- **默认裁决（否决窗口内可推翻）**：
  - 「窗口」= 本应用单窗口内的会话列：触发点为侧栏点击、bootstrap 自动选中的首个会话、host 重启后活跃会话、发消息前兜底。用户示意代码将 ensureLive 放主进程（多窗口形态）；本仓库选择真相在渲染层（选择态/激活态归渲染层 store，主进程 resume 路由保持无状态），去重表随选择真相放 controller。
  - 对账数据源按注册表各行 cwd 逐目录 `list_saved` 聚合（hub 语义：无 cwd = host 进程 cwd，不适用）；某 cwd 列举失败时该目录行**保留占位**（暂态错误不得删恢复依据），仅列举成功且确认缺失才删行。
  - 空 sessionPath 行（从未有首条消息）在对账时清理（沿既有 resumeAll 语义）。
  - parked 会话关闭走既有 `session/stop`（hub 幂等：未知 id 也 success）→ 注册表删行，无需新面。

## 测试口径

主进程（`apps/electron/src/main/__test__/pai-runtime-reconcile.test.ts`，fake host port 经 `createHost` 注入）：

1. 症状回归：注册表 3 行在盘 → 启动 **0 个 `thread/resume`**；`sessions()` 全 parked 占位（title 取注册表行）。
2. 文件确认缺失（list_saved 成功不含该路径）→ 删行 + `sessionRemoved`。
3. 某 cwd 的 list_saved 失败 → 行保留为占位（不删）。
4. sessionPath null 行 → 清理。
5. onRestart 钩子 → reconcile（无 resume），live 视图回落 parked。
6. resume 路由保留注册表标题（症状回归：不再抹成 New conversation）。
7. resume 响应换 id → 旧行删除 + `sessionRemoved` + 新行落库。

渲染层（`live/__test__/controller-lazy-resume.test.ts` + actions 用例）：

8. selectSession(parked) → 恰一次 `session/resume`；在途重复点击去重（1 次命令）。
9. resume 失败 → 通知条 + activeThreadId 不变 + 占位保留（无自动重试）。
10. resume 成功 → 以响应 id 激活；同 id 不重复激活。
11. submitDraft 于 parked 活跃会话 → 先 resume 后 prompt（用返回 id）；resume 失败 → `resume_failed` 原因 + 通知。
12. bootstrap 自动选中 parked → 自动唤醒；失败 → 通知（不崩、不重试）。
13. `sessionUpdated(parked)` 命中活跃会话 → 自动唤醒（host 重启链路）。
14. openSavedSession 同路径已 live → 直接激活、零 resume 命令。
15. 激活 effect：parked→live 翻转重拉水化（use-live-workspace 层）。

边界与异常清单：resume 超时/写失败（outcome reason 透传通知）；host 未启动（`host_unavailable` → 通知，占位保留）；cwd 为空串的行不参与删行判定（保留占位）。
