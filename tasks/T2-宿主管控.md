## 契约

```typescript
// packages/infra/process —— 实现 core 的 AgentHostPort
class HubSupervisor {
  start(): Promise<void>                       // spawn(bun, hubEntry, env 见方案 2.1)
  stop(): Promise<void>                        // 优雅：关 stdin → 等 exit（5s 兜底 kill 进程组）
  killGroup(): Promise<void>                   // SIGKILL 进程组（挂死/恢复路径）
  send(line: string): Promise<void>            // stdin 串行队列 + 背压 + EPIPE 快速失败
  // 事件（恰好一次语义）：
  //   frame(f)          —— 委托 T1 Framer 解出的帧原样上抛
  //   heartbeat()       —— 心跳帧（供 watchdog 计时）
  //   exit(code, expected)
  //   hangDetected()    —— 内部 watchdog：>10s 无心跳（一次性闩锁，心跳恢复才复位）
}
recoverAll(): Promise<ResumeReport>            // 重启 hub → 按 StorePort 快照逐个 thread/resume（编排归 T4 注入回调，本包提供原语）
```

- 错误形态：send 对已死 hub reject（中性英文）；spawn 失败归一化 exit(null,false)。
- 时序：exit 恰好一次且最后（error/exit 双触发闩锁）；恢复原语可被 T4 编排（重启 1 次 → 成功率报告）。

## 问题域

- 处理：hub 进程生命周期（spawn/优雅停/强杀/进程组）；stdin 写队列（背压/EPIPE/毒化自愈）；心跳 watchdog（10s 判死闩锁）；stderr 采集（环形 64KB + 特征回调钩子位）；bun/hub 路径与哈希校验注入（实现归 T7 装配，本包消费 RuntimeConfig）；恢复原语。
- 不处理：thread 语义与恢复编排（T4）；帧内容解析（T1）；OS 沙箱（hub 负责自行包裹，Pai 不经手）；孤儿进程清理（hub 在 stdin EOF 时自行优雅退出并 flush，无需独立清理机制）。

## 并发/一致性预算

- 定时器恰 1 个（watchdog 1s tick）；写队列串行、背压 drain、死亡快速失败；stop ≤5s；stderr 环形 64KB；进程组 kill 兜底 3s。

## 裁决

- fake-hub 承担全部进程语义单测（真 hub 只留 integration）：沿用既有裁决（崩溃/挂死不可脚本化稳定复现）。
- 不做独立孤儿清理机制（hub 的 stdin EOF 优雅退出语义已覆盖该场景）：**默认裁决**，否决窗口至定稿。

## 测试口径

- 契约断言：exit 恰好一次且最后；hangDetected 一次性；send 拒绝两形态穷举；stop 幂等。
- 边界/竞态：ENOENT/权限；kill 已死；watchdog 与 exit 竞速；背压极端；信号杀死（signalCode 路径）。
- 表驱动：写失败形态表、watchdog 矩阵。
- 分层：单元（fake-hub）+ integration（M5 真 hub，夜间门）。
