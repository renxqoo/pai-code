# 会话权限模式操作栏切换 方案
> 状态：已实施（四门全绿；未提交——工作区混有 T12/T13 在途变更，提交留待协调）
> 级别：中
>
> 需求：每个对话可独立切换权限模式，入口在输入框下方操作栏。
> 来源：用户指示（2026-09-08）；即《T11-裁决与实施》§裁决表第 5 项登记的
> 「composer access 选择器以『会话权限』真语义（sidecar mode）回归」——
> G2（会话级规则 sidecar 通路）已落地，本任务补回操作栏入口。

## 契约

- 不新增 IPC / hub 命令。全部复用既有通路：
  - 读：`permission/sessionRead {threadId}` → `{ rules, source: 'thread' | 'global' }`
    （hub 侧返回当前生效规则：有 sidecar 用 sidecar，否则用全局文件内容）。
  - 写：`permission/sessionWrite {threadId, rules | null}`（null = 删 sidecar 回退全局）。
- 渲染层新动作 `setSessionPermissionMode(mode)`（`LiveWorkspaceView.actions`）：
  以**当前生效规则为基线只改 mode** 写会话 sidecar；同模式返回 true 且不写（不无谓造 sidecar）。
- 纯函数 `nextSessionRulesForMode(current, mode)`（renderer `live/`）：
  同模式返回 `null`（无操作哨兵）；否则返回深拷贝 + 新 mode。
- `clonePermissionRules(rules)`（contracts `permissions.ts`）：深拷贝（数组引用不共享），
  为 `PermissionRules` 的单一真相拷贝实现；permissions-section 私有 `cloneRules` 删除改用。
- UI：操作栏（`ComposerActionsRow`）effort 下拉后新增权限模式下拉
  （`MenuButton` + Shield 图标 + 当前生效模式标签）。数据未加载（`sessionRules === null`）时控件整体不渲染。

## 问题域

- 处理：
  - 输入框操作栏展示**当前生效**权限模式（sidecar 优先，否则全局）；
  - 点选三模式（ask / allow-all / block-all）之一 → 写会话 sidecar（保 patterns 只改 mode）；
  - 「跟随全局规则」菜单项（仅会话已有 sidecar 时可用）→ 删 sidecar；
  - 切会话时随现有 effect 拉取会话规则进 store。
- 不处理：
  - 受信（trusted）切换——归属 ThreadHeader 重开菜单（`reloadSessionTrusted`），与权限模式是两件事；
  - pattern 编辑——归属设置页权限分区（操作栏只切 mode）；
  - 全局模式切换——全局规则影响全部会话，入口留在设置页（操作栏只动当前会话 sidecar）；
  - allow-all 二次确认弹窗——菜单点选已是显式两步动作，不加确认（默认裁决）；
  - 生成中禁用——`set_permission_rules` 是 host 本地文件命令（不唤醒 worker），
    hub 下次工具调用热读生效；生成中允许切换（默认裁决）。

## 并发/一致性预算

- 每次会话切换至多 1 次额外 `permission/sessionRead`（host 本地文件读，毫秒级）；无新增定时器。
- 在途竞态：会话切换后旧会话的 sessionRead 响应必须丢弃——判活守卫加在
  `controller.readSessionRules`（响应落地前 `store.activeThreadId !== threadId` 即丢弃，
  与 `refreshAgents` 同型）。这同时修掉设置页 stableReadSessionRules 的同类理论竞态。
- 全局规则失效链：`permission/read|write` 成功后同步重拉活跃会话生效视图
  （source=global 时 rules 即全局内容，防操作栏以陈旧全局为基线切模式丢 patterns）。
- `store.setActiveThread` 切换同步清空 `sessionRules`（同值重设不清；防渲染帧残留一帧旧会话模式）。
- 会话规则写链：`stableWriteSessionRules` 的「写 + 回读」成对串行排队
  （模块级 promise 链，与 `skillToggleChain` 同型），防并发写后回读乱序覆盖视图。
- 写路径复用既有 `writeSessionRules`（主进程已带 `permission_write_session` 审计）。

## 裁决

- 「权限模式」= `PermissionRules.mode`（ask/allow-all/block-all）会话 sidecar 语义，
  非 trusted（项目扩展加载）——按 T11 §裁决表第 5 项既定登记。
- 无 sidecar 时切模式：以当前生效（全局）规则为基线建 sidecar 只改 mode——
  防止「切个模式丢掉全局 patterns」的隐性损失（默认裁决）。
- 同模式点选 = 无操作不写（含无 sidecar 时选到与全局相同模式：不造 sidecar）。
- 菜单项文案复用 `settings.permissionsMode*` 与 `permissionsFollowGlobalAction`（同一事实不二写）；
  仅新增 `composer.permissionMode`（aria/tooltip）。
